# 交互与反馈

交互围绕一次能改变判断的学习动作设计：预测、操纵、比较、检索、解释或修正。先问“不交互是否仍能理解”，若答案是是，就静态表达；若需要交互，明确它改变的条件、可观察后果和下一步解释。

一次先改变承担解释责任的变量，保留前态、参照和操作痕迹；操作尽量低成本、可逆、可暂停、可回看、可重试。结果至少在形状、数值、结构或语言中留下证据，不能让动画承担唯一证据。复杂系统先冻结不相关变量，再逐层释放自由度。

反馈贴回原对象并保留作答上下文：指出哪条证据支持或推翻判断、哪一步推理失效、下一次应观察什么。错误是诊断材料，不只换颜色或报对错。键盘、焦点、ARIA 和动态状态与指针操作等价。

流程语义遵守现有 UI Kit：无按钮或控件承载动作时，使用“下拉提示”确认进入下一阶段；已有按钮或控件完成动作时，使用“直接弹出”或原位反馈。Select 只做互斥选择，ExplainPanelButton 只做邻近解释，Feedback 承载结果/错误/提示；禁止另造 modal、全局 toast、悬停独占解释或重复的 hint 机制。

涉及动态模型和随机试验时，按需读 [simulation](../visuals/simulation.md)。状态归属与组件 API 在编码阶段处理。
