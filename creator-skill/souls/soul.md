# Soul

记录用户在课程创作中的长期偏好。这里只记录会实际影响教学设计、视觉设计、交互和工作方式的信息，不记录与创作无关的人格判断。

## 用户喜欢


### 任天堂式教学体验

- 喜欢把知识规律设计进页面和操作本身，不先告诉学生完整规则。
- 通过视觉暗示、有限自由度、直接操纵和即时反馈，让学习者自己发现“原来是这样”。
- 新能力应像游戏机制一样逐步解锁，后续继续复用已经学会的操作。
- 追求直觉、自然、轻松和恰到好处的惊喜，不喜欢表面的游戏化装饰。

### 多邻国式学习节奏

- 喜欢把较大的学习目标拆成连续的小型认知闭环。
- 一页或一个阶段尽量形成“尝试或预测 → 立即反馈 → 理解一个规律 → 马上再用一次”。
- 喜欢让之前学过的知识在后续页面通过变式自然再次出现。
- 喜欢持续而明确的学习进展感，让学生不断产生“我又会了一点”的感觉。
- 不依赖积分、徽章、签到等表层游戏化维持学习兴趣。

### 视觉设计

- 喜欢页面有一个非常明确的**视觉主角**，学生第一眼就知道应该看哪里。
- 喜欢少量大区域和强空间关系，不喜欢大量等权重小卡片。
- 喜欢图形真正承担解释，而不是“左边文字，右边随便配一张图”。
- 喜欢根据知识结构决定构图，不为了统一而把所有页面套成相同模板。
- 喜欢克制、现代、学术、干净的视觉效果，同时不能显得冷淡或无趣。
- 喜欢 React 能真正实现的设计，而不是依赖难以落地的复杂视觉特效。
- 喜欢适当留白和清晰层级，不追求把 1600×900 填满。
- 同一个知识对象跨图片、图表、公式、代码和交互时，喜欢保持颜色、名称和视觉对应连续。

### 图片与真实材料

- 背景介绍、人物故事、历史事件、经典实验等页面，喜欢主动寻找真实图片、原始论文、档案或历史材料。
- 真实素材难以获得或不适合直接使用时，喜欢教材式重绘或生成教学插图。
- 图片应该帮助学生快速建立情境、理解对象或产生兴趣，而不是装饰。
- 不要求在学生页面上堆放版权、许可、访问日期等与学习无关的信息。
- 教学重绘和生成插图可以自由服务讲解，但不能冒充真实历史原图或真实数据。


### 表达方式

- 喜欢直接、准确、自然的语言。避免AI味。
- 教学文字应让普通学生容易理解，但不能为了通俗牺牲事实准确性。
- 学术内容需要正式、地道、书面，但避免故作高深。
- 喜欢短而有效的说明，能用图和操作解释时不使用长段文字。
- 标题最好直接提出问题、现象或结论，不喜欢空泛口号。

## 用户不喜欢

- 不喜欢 Dashboard 式、后台管理系统式、多层卡片套卡片的 PPT。
- 不喜欢页面所有元素大小和权重接近，没有明显视觉中心。
- 不喜欢为了“高级感”堆渐变、蓝色光圈、光带、粒子、玻璃效果等廉价科技感。
- 不喜欢图片只是装饰，与当前论证没有关系。
- 不喜欢用 CSS 假造本应寻找真实素材的历史记录、人物材料或实验材料。
- 不喜欢历史背景页直接做成普通统计学解释页，过早出现后续结论。
- 不喜欢第一屏同时讲背景、概念、方法和结论，分散注意力。
- 不喜欢先给大量定义、术语和公式，再要求学生理解。
- 不喜欢为了互动而互动，例如没有认知意义的按钮、动画和拖拽。
- 不喜欢需要一大段文字说明“这个控件应该怎么使用”的交互。
- 不喜欢错误反馈只有“正确”“错误”或简单变色。
- 不喜欢把学生当作被动观看者，希望尽量让其预测、操作和发现。
- 不喜欢固定模板压过知识本身的结构。
- 不喜欢 Agent 在开始创作前加载大量规则、表格、评分体系和流程文档，导致生成结果保守和趋同。
- 不喜欢为完成流程额外生成无实际用途的 Brief、Visual Plan、评分表等中间产物。
- 不喜欢抽象、晦涩、只有 Agent 作者自己懂的术语，例如为了显得专业而创造复杂概念。
- 不喜欢明显的 AI 味表达、空话、元话语和删掉也不影响含义的句子。
- 不喜欢完整课程被粗暴塞进少量巨大页面文件，呈现出快速 Demo 式工程结构。
- 不喜欢为了一个局部修改推翻用户已经认可的其他页面。
- 不喜欢把版权、许可、访问日期等素材管理信息展示给学生，干扰教学内容。
- 不喜欢仅仅因为已有组件存在，就强行把知识塞进组件的既定形状。

## 推测用户可能喜欢

以下内容尚未完全确认，创作时可以尝试，但应根据后续反馈调整。

- 可能喜欢在熟悉生活场景与真实科研材料之间建立更强联系，让抽象知识既有直觉入口又有真实证据。
- 可能喜欢课程整体带有轻微的探索感、发现感和成就感，但视觉上仍保持专业、克制，不做儿童化游戏界面。
