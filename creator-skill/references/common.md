# 共同约束

本文件适用于课程规划、单页设计、工程实现和验收的每一个阶段。

## 使命与判断标准

课程页面不是把内容放进网页，而是把认知过程设计成可看见、可理解、可记住的界面。成功不以页数、组件数、交互数或视觉复杂度衡量，而看学习者能否更快：

- 看见关键关系；
- 形成预测并发现矛盾；
- 建立解释；
- 用自己的话复述并迁移。

设计感服务于重点、关系和理解，不是附加装饰。不要为填满页面、达到页数或制造科技感加入没有教学作用的内容。

## 执行优先级

冲突时依次服从：

1. 老师明确要求与原始材料事实；
2. 教学目标与认知正确性；
3. 当前仓库代码与 `AGENTS.md` 的工程约束；
4. Shared UI Kit 的语义、状态和可访问性规范；
5. 可读性、稳定性与可访问性；
6. 视觉设计与交互丰富度；
7. 风格创新与装饰效果。

不得以视觉效果牺牲事实，以交互丰富度牺牲认知清晰度，以模块个性绕开 Shared UI Kit。

## 工程事实来源

默认以 `develop` 分支为实现基线；若任务明确指定其他目标分支，以该分支为准。事实来源优先级为：

```text
当前代码与 AGENTS.md
→ modules/shared/react/ 当前实现
→ src/app/ 当前注册与路由
→ active module 当前实现
→ 模块 README、设计说明和历史文档
→ 其他分支
→ modules-legacy/
```

`modules/` 是唯一 active module 树。应用代码和 active module 不得从 `modules-legacy/` 导入、获取、链接或加载运行时代码与资源，也不得注册一个只存在于 legacy 中的模块。

现有 active module 也可能是迁移期实现。可以研究其教学经验，但不要假定每处代码都是最佳实践。尤其把 `modules/Neuron-Guide` 当作设计研究对象，而不是模板：学习其节奏、叙事、状态和反馈判断，不机械复制页面结构、色彩、卡片、章节或私有实现。

## 事实、推断与来源

始终区分：

- 原始材料明确给出的事实；
- 外部资料；
- 教学示意数据或例子；
- 根据材料作出的设计推断；
- 仍需老师确认的关键内容。

材料中的公式、数据、定义、人物、事件和结论不得随意改成不同事实。教学示意数据不得伪装成原始数据。

只有会显著改变课程方向、事实正确性或教学目标的不确定性才阻塞并请求确认。其他细节作出保守、合理、可解释的判断后继续。

真实人物、历史事件、研究结论、数据集和外部媒体必须承担教学作用。外部素材应保存在对应 active module 中，记录作者、来源、许可或访问日期，不依赖运行时远程地址。优先公共领域、开放许可或项目自有素材。自绘 SVG、CSS、Canvas、数据可视化或 AI 生成素材也应在 README、`sources.md` 或注释中说明用途与来源。

## 跨形态一致性

PPT、Guide、图表、公式、视频、动画、实验、来源和详细解释可以表达同一知识，但必须指向同一概念骨架。图中的对象、文字定义、公式变量和交互结果必须互相对应。

PPT 与 Guide 共享教学目标、知识结构、课程单元、关键证据、领域计算、共享状态和学习顺序；它们不必共享完全相同的版式和展开深度。

## 教学硬约束

- 一页只有一个占主导地位的问题或判断；辅助信息不得争夺注意力。
- 公式用于压缩已经建立的关系；第一次出现时解释变量，并与可观察现象对应。
- 图表展示关系和变化；文字命名、提问和解释；交互产生静态页面无法提供的新证据；来源提供可信度。
- 不原样重复同一内容于标题、图和正文。
- 解释贴近被解释对象；图例贴近图表；变量说明贴近公式；反馈贴近触发操作。
- 颜色、位置、动画顺序和标注承担稳定语义，不随机装饰。
- 复杂推导、流程和实验分段呈现，不一次堆出全部参数、结论和说明。
- 交互不是完成度指标。若不能改变学习者可观察的证据，就不要添加。

## Shared UI 与 Typography

实现前查看 `modules/shared/react/index.ts` 及相关实现，以当前导出为准。Shared 已有的能力必须优先复用；模块只保留课程特有的知识可视化与交互。

所有独立教学文本使用 Shared `Typography`，包括页面标题、小节标题、解释、标签、公式说明、状态说明和辅助信息。Shared 组件内部文字不需外包 Typography。SVG、Canvas、图表刻度、图表内标签和公式渲染器可使用其专用文本，但应遵循 Shared token 与课程视觉等级。

模块 CSS 不得重定义 Shared Typography 的字体、字号、字重或行高；需要变化时使用现有 `variant`、`tone`、`align`、`wrap`、`className` 或 token。

## PPT 画布硬约束

Web PPT 为 `1600 × 900`。内容必须自然收进画布：

- Grid/Flex 子项可收缩，使用 `min-width: 0`，参与布局时按需设置 `max-width: 100%`；
- 网格使用比例轨道，优先 `minmax(0, <fraction>fr)`；
- 公式、媒体、SVG、Canvas 和交互组件不得撑破父容器，并设置合适的 `max-width: 100%`；
- 列、间距和内边距总和必须适合父级内容盒。

禁止多个固定像素 `min-width` 拼一行，禁止用 `overflow-x: auto`、父级裁切或长期自动缩放掩盖问题，禁止为塞入内容把文字缩得极小。

完成 PPT 布局变更前，验证 `.ng-ppt-slide-surface` 的所有后代边界框均未超出 slide surface。

## 范围与协作

默认按“理解材料 → Brief → 认知地图 → 页面大纲 → 小批量实现 → 反馈 → 调整”合作。不要因小问题反复阻塞；设计推断可在交付时说明。如果老师明确要求直接完成，且不存在必须确认的关键问题，则自主推进。

不要把自然连续的一步强行拆页，不要把多个独立问题塞进一页，也不要从知识点列表机械映射页面。最终页面必须能解释：学习者此刻观察什么、什么证据改变理解、为什么这一页现在出现，以及结束后能否自行解释。
