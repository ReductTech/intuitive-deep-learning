# 单页设计与排版

设计、修改或精修一个课程页面时读取本文件。先遵守 [common.md](common.md)。如尚未确定页面的主问题与前后关系，先读取 [course-planning.md](course-planning.md)。

## 1. 单页优先

默认一次只设计一页。除非老师明确要求，或多页之间存在必须同时处理的强依赖，不要一次铺开整套页面代码。

开始前先明确：

```text
这一页的主问题是什么
最重要的视觉证据是什么
学习者第一眼应该看哪里
版面为什么适合当前内容
与前一页、后一页如何衔接
```

当前页未达到较高完成度时，不急于生成后续页面。不同页面可以有不同布局、视觉重心与构图策略。

## 2. 先构图，再填内容

课程页面不是文档排版。布局由认知任务决定，而不是从二栏、三卡片、Hero 或统一模板出发。

- 讲趋势：图表成为主视觉，文字围绕图表服务。
- 讲历史背景：材料、图片、时间信息与研究问题构成叙事。
- 讲公式推导：突出推导路径与变量对应，不机械分栏。
- 讲对比：在同一参照系中并置或前后对照，不拆成孤立卡片。

阅读顺序必须明显；不要连续多页复用同一标题区、内容区和说明区。

## 3. 明确视觉重心与三级层次

除纯过渡页外，每页必须有一个视觉主角，例如关键图表、关系图、公式与图形组合、历史材料、对比结构、局部放大或实验区域。不要平均铺开多个权重相近的小块，也不要让标题、正文、卡片和按钮同等醒目。

三秒内应能区分：

```text
哪里最重要
哪里是解释
哪里是补充
```

页面至少形成三级：

1. 主层：最重要的证据、图形或问题；
2. 支撑层：解释、比较、补充或局部说明；
3. 注释层：标签、来源、变量解释、脚注与提示。

通过尺度、位置、对比和留白区分层级，不要让所有内容面积、字号、颜色和边框样式近似。

## 4. 把关系画出来

因果、数量变化、趋势、分布、时间顺序、结构组成、方法对比、错误与修正、输入输出、真实值与预测值、局部与整体，只要适合可视化就优先画出来。

图表负责关系，文字负责命名和解释，公式负责压缩已建立的关系。不要用长段文字解释一个能直接画出的关系。

图、解释、图例、标签、公式和变量说明在空间上贴近。课程原则应直接体现在界面中：一个主问题、一个先被看见的重点、稳定颜色语义、先观察再判断、清楚的下一步。

## 5. 视觉丰富度与留白

有效的丰富度来自图文关系、尺度差、主次分层、材质与模块对比、图表和说明配合、真实材料、局部放大、标注与状态变化。

不要依赖过多渐变、发光、流光、随机装饰图形、无教学作用插图、同款卡片或花哨动画。精致应表现为间距舒适、对齐严格、主次清楚、重点明确和信息密度合理。

留白必须承担聚焦、观察空间、信息分界或节奏停顿的作用。若内容只是缩在角落，或零散模块没有整体构图，页面仍未完成。

## 6. 内容密度

克制不等于空。不要用一句结论和一个无意义交互撑满屏幕。页面应完整承担当前认知任务，可包含真实背景、核心问题、概念、例子、对比、反例、误解、实验、预测、练习或小结，但仍只服务一个主问题。

内容是否足够按认知任务是否完整判断，而不是按字数判断。过密时重新分配或删减，不通过极小文字、裁切或缩放解决。

## 7. 判断交互是否必要

只有当交互改变学习者能观察到的证据时才保留。每个交互必须回答：

1. 操作前学习者应该猜什么；
2. 操作改变哪个可观察量；
3. 变化如何反馈概念；
4. 操作后学习者应该能解释什么。

无法回答时取消交互。带实质交互的页面默认不超过整套课程一半；背景、证据、观察图、推导、对比、反例、案例、总结和过渡都可以是无交互页。

阅读型步骤使用 Shared LessonFlow 的合适流程能力，例如 `cue`、`scroll` 或 `immediate`。需要滚动、触摸上滑或键盘推进时复用 `LectureAdvanceCue` 或 Shared 中等价能力，只显示轻量提示。只有必须确认、提交答案或完成操作时才使用按钮，不添加“继续”假按钮。

Shared 无法表达课程特有操作时，才实现画布绘制、棋盘格选择、图表图例操作、图像标注、几何点拖动、模型结构操作、时间轴或模拟器等专用交互；它们仍须遵循 Shared token、焦点、键盘和可访问性要求，并考虑 reset。

## 8. 素材进入页面的规则

课程背景、历史叙事、真实对象、实验场景、地理位置、人物、装置、档案、显微图像、结构示意或空间关系能显著提升理解时，可以搜索、下载、自绘或生成素材。

- 对背景介绍、人物、历史事件、真实实验和装置，应主动联网搜索可靠图片与原始材料，不要默认退回纯文字或通用占位图。
- 适合使用的外部图片应下载到当前模块的 `assets/`，记录来源、作者、许可和访问日期，避免运行时依赖远程地址。
- 缺少合适真实素材，或需要辅助背景、场景复原和统一风格插图时，可以调用环境提供的文生图能力；生成时根据当前课程单独编写提示词，不复用固定视觉配方。
- 真实材料证据更强时优先真实材料。
- 真实素材不足时可生成风格统一的背景、插图或结构示意，但生成图不得替代图表、公式或文字承担的精确信息。
- 关键文字、数字、标签、图表、公式和结论优先保留为 DOM、SVG 或可交互组件；背景、纹理和辅助视觉可以用图片。
- 整套课程保持统一、节制、可信的视觉气质，不要在写实、卡通、科技海报和极简表单间随机跳变。

来源、许可与文件归属遵守共同约束。

## 9. PPT 布局

对 1600×900 画布，在共同约束的基础上逐层检查：

- 主视觉和支撑区域使用能收缩的比例布局；
- 所有 Grid/Flex 子项设置合适的 `min-width: 0` 与 `max-width: 100%`；
- 公式、SVG、Canvas、媒体和交互不超出父级；
- 文本不因固定列宽被压成窄条；
- 没有横向滚动、隐式裁切或明显自动缩小；
- `.ng-ppt-slide-surface` 后代边界框全部位于画布内。

自动缩放只能是安全兜底。若页面只有明显缩小才能放入画布，重新设计信息密度或布局。

## 10. 单页验收

完成后逐项回答：

```text
1. 唯一主问题是什么
2. 第一眼应该看哪里
3. 提供了什么新证据
4. 图、文字、公式与交互分别承担什么职责
5. 有无删掉也不影响理解的元素
6. 若有交互，操作前预测什么
7. 操作改变哪个可观察量
8. 完成后学习者应该能说出什么
9. 为什么自然通向下一页
10. 1600×900 下是否完整可见
11. 是否有明确视觉重心
12. 主层、支撑层、注释层是否清楚
13. 是否为当前内容专门构图，而非套模板
14. 图表、文字、说明和标签是否紧密关联
15. 留白是否有明确作用
16. 是否有足够层次与完成度
17. 学习者能否迅速抓住重点
```

第 3、8、9 项答不清时重新设计甚至删除。第 11、12、13、17 项不能肯定时，页面仍停留在普通排版层面。

## 11. 必须避免的单页失败

- Hero + 三卡片、三等列或万能二栏成为默认答案；
- 所有内容块尺寸接近，仅用阴影、圆角或卡片数量表现层级；
- 只有文字和边框，没有真正视觉证据；
- 图表存在却不是视觉主角；
- 用渐变、发光、随机颜色或无关插图制造设计感；
- 每页都有按钮，或滑杆只改数值却不反馈概念；
- 错误答案只判错，不解释原因；
- 复杂交互无 reset，结果无法用语言解释；
- 用 `overflow: hidden`、横向滚动或自动缩放掩盖越界；
- 多个固定像素列互相挤压，图表、公式或 Canvas 超出画布；
- 为塞内容缩小所有文字。
