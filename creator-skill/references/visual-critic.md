# Screenshot Visual Critic

React 页面可运行后、宣布完成前读取本文件。Critic 评价真实画面，不以代码优雅或组件复用程度替代视觉判断。

## 证据采集

1. 在真实 `1600×900` viewport 打开目标 PPT slide；
2. 等待字体、图片、图表和初始状态稳定；
3. 截取完整 slide surface，而非局部组件；
4. 同时运行 `.ng-ppt-slide-surface` 后代边界框检查；
5. 有关键交互时，另截最能证明理解变化的状态。

截图与边界检查回答不同问题：前者判断注意力与构图，后者证明没有越界。两者都必须完成。

## 无代码视角审阅

先像第一次看到课程的学习者一样看截图，再看实现。逐项判断：

- 第一眼落在哪里，是否正是核心知识；
- 核心证据是否成为最大、最清楚的对象；
- 第二眼是否自然通向解释或判断；
- 图形是否承担了本该承担的关系，还是文字在替图解释；
- 文字是否超过注意力预算，删除后视觉证据能否自己说话；
- 是否像 Dashboard、模板落地页或 Card 套 Card；
- 是否有大片无作用空白，或多个小区域平均竞争；
- 真实素材是否真正进入画面并承担证据作用；
- 颜色、位置、连线和动画是否有稳定语义；
- 解释、标签、公式是否贴近被解释对象；
- 换成另一门无关课程的标题后，80% 构图是否仍成立；若是，构图可能尚未属于当前知识；
- PPT 与 Guide 是否各自适合其观看距离和任务，而非同一 DOM 的删减版。

## Critic 输出

内部形成简短结论：

```text
第一眼 / 第二眼 / 最终判断
最强之处
最主要的一个失败
保留什么
删除什么
需要怎样重构空间关系
```

不要列十几个同权重微调项。优先找出最妨碍理解的结构问题。

## 重构优先级

```text
重构布局
> 删除内容
> 改变表达媒介
> 调整对象尺寸
> 最后才微调 padding、圆角、边框与 shadow
```

Critic 失败后重新截图，直到主视觉、注意路径、知识专属性和画布 containment 同时成立。仅修改 CSS 数值而未解决主要失败，不算完成一轮重构。
