# 工具脚本规范

用于维护 `scripts/` 中供智能体调用的工具。按用途分为 `module/`、`checks/`、`media/`、`analysis/`、`common/`、`tests/`，模板单独放在 `templates/`，不再增加更深层级。统一入口、清单与依赖文件保留在根目录；测试和内部辅助文件不强套命令行模板。

## 新建脚本

直接复制 [Python 模板](../../scripts/templates/python_tool.py)或 [Node 模板](../../scripts/templates/node_tool.mjs)到对应的工具分类目录并改名。分类目录与 `templates/` 同级，共用辅助文件的导入路径无需调整。

修改文件头说明，在参数定义函数中添加实际参数，再实现 `run_task()` / `runTask()`。保留 `main()` 和执行入口，完成业务与必要测试后再登记 `catalog.json`。Node 的业务说明与 `printHelp()` 文案同步填写。

模板未实现业务时会明确返回错误和退出码 `2`，不会假报成功；`--help` 与导入文件仍可直接使用。模板本身不登记到工具清单。

## 文件组织

按“文件说明 → 导入与常量 → 参数定义 → 业务函数 → main → 执行入口”排列。

- 文件头简述用途、读取范围、写入范围与覆盖行为。
- Python 参数集中在 `build_parser()`，Node 参数集中在 `buildParser()`；每个参数说明类型、默认值、允许值、路径含义及必要的组合条件。
- 主要业务函数补齐简短说明与适用的类型标注；注释解释原因和保护逻辑，不逐行翻译代码。
- `main(argv)` 负责参数解析、执行编排、输出和退出码。业务函数返回数据，不负责整份命令结果的打印。
- 导入文件不解析命令行、不扫描模块、不启动进程或服务。可选依赖在实际使用时加载，`--help` 不依赖浏览器、模型或上传服务。

## 输出与退出码

- 正常执行向 stdout 输出一份 JSON，包含 `status` 和工具自身的结果字段；产出文件使用可定位的路径。
- 进度与诊断写入 stderr。帮助及 `tools.py list` 继续使用便于阅读的文本。
- 状态可区分 `ok`、`passed`、`failed`、`error`，以及创建工具的 `created`、`unchanged`、`would-create` 或 `dry-run`。
- `0`：执行成功、检查通过或无需修改；`1`：检查已完成但未通过；`2`：参数、依赖、输入或执行错误。参数解析失败由原生命令行解析器输出帮助与错误，不额外包装。
- Python 共用 `common/_common.py` 的输出函数，Node 共用 `common/_cli.mjs`；不增加装饰器、注册框架或通用结果模型。

## 维护边界

路径边界、已有文件保护、覆盖条件和资源清理由代码执行，并用行为测试验证。保持已有业务能力、命令名称与必要的转发入口；调用参数以脚本的 `--help` 为准。

`catalog.json` 只维护工具索引、运行环境、依赖、执行效果和别名所需的固定参数，不再重复维护完整参数用法。通用调用方式见[工具索引](../tools.md)。
