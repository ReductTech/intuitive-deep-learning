# 课程验收与复盘

验收一个页面或整套课程时读取本文件。先遵守 [common.md](common.md)。单页视觉验收还应读取 [page-design.md](page-design.md)，工程验收应读取 [implementation.md](implementation.md)。

## 1. 单页验收

使用 [page-design.md](page-design.md) 的 17 项单页检查。特别关注：

- 是否只有一个主问题；
- 是否提供能改变理解的新证据；
- 学习者结束后能否自己解释；
- 是否自然连接下一认知步骤；
- 是否有明确视觉重心和三级层次；
- 是否像为当前内容专门构图；
- 1600×900 下所有内容是否真实位于画布内。

## 2. 整套课程验收

### 教学

- 是否有清晰认知旅程；
- 是否有重复页面或概念跳跃；
- 是否适时使用反例；
- 是否让学习者形成自己的判断；
- 是否有检索或迁移机会；
- 公式是否对应可观察关系。

### 视觉

- 是否有来自知识结构的统一视觉隐喻；
- 是否避免模板化 SaaS 页面与无意义科技感；
- 颜色是否承担稳定语义；
- 每页阅读顺序是否明确；
- 页面之间是否有变化，但整套视觉气质仍统一可信。

### 交互

- 交互是否少而有力；
- 每次操作是否带来新证据；
- 是否存在假按钮、无意义滑杆、弹窗或动画；
- 错误反馈是否解释原因；
- 键盘、焦点、禁用态和 reset 是否合理。

### 工程

- 是否复用当前 Shared UI Kit 与 API；
- active code 是否完全不依赖 `modules-legacy/`；
- 是否正确使用 Provider 与 LessonFlow；
- 是否处理适用的 hydrate、error、loading、reset、revisit；
- 是否存在重复领域计算；
- Guide、PPT 和 preview 是否来自一致课程结构。

### PPT

- 是否完全位于 1600×900；
- 是否没有横向滚动、隐式裁切或明显自动缩小；
- 是否没有极小文字；
- 所有 Grid/Flex 子项、媒体、公式、SVG、Canvas 和交互是否自然收进画布；
- 是否实际确认 `.ng-ppt-slide-surface` 后代边界框没有越界。

### 来源

能否明确指出哪些是原始材料事实、外部资料、教学示意、设计推断和仍需确认的内容；外部素材是否有作者、来源、许可或访问日期记录。

## 3. 教学复盘

删除或重做：

- 重复解释和不必要页面；
- 无意义交互与控件；
- 不产生理解的装饰；
- 只重复正文的阶段总结；
- 没有变量解释或可观察对应的公式；
- 只判对错、不揭示原因的反馈；
- 与主问题争夺注意力的辅助信息。

## 4. 最终判断

优秀课程模块不能只是信息排版、课本变网页、静态 PPT 加按钮，或通用模板替换标题。最终必须回答：

```text
学习者此刻正在观察什么
下一步会产生什么预测
什么证据会改变理解
为什么这一页现在出现
为什么这个交互值得存在
为什么这个视觉形式属于这门课
这一页结束后能否自己解释
```

最好的模块不是最复杂的模块，也不是最像某个既有模块的模块，而是由这门课的知识结构自然长成。Shared UI Kit 统一语言、状态和可访问性；课程模块表达知识自身独特的结构。
