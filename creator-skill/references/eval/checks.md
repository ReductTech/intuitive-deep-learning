# 基础检查与验收

页面制作与修改后必须执行基础检查：**完成页面 → 基础检查 → 修复并复查 → 展示给用户验收**。不为基础检查生成 Rubric 分数。普通自检仍须发现并处理明显的事实、布局和交互错误。

仅在用户明确要求打分、评分或执行 Rubric 时，额外加载 [Rubric Evaluation](rubric-evaluation.md)。“检查一下”“看看有没有问题”“优化一下”不自动触发评分。评分不替代基础检查或用户验收。

## 检查范围

- 新页面：当前页默认状态及本次实现涉及的关键交互状态。
- 页面修改：受影响页面和状态。
- 页序、入口或共用逻辑变化：扩大到实际受影响范围。
- 整套制作完成：补充整体页序、入口和内容对应检查。
- 仅修改 Skill 文档：运行 `check.skill creator-skill` 并核对引用，不启动页面检查或评分。

基础检查必须执行，不等于每次运行全部工具。按实际改动选择适用项；不适用时说明原因。检查证据须对应当前实现，旧截图和旧统计不能证明新版本通过。

## 必须覆盖的检查

### 工程与模块

对 TS/TSX 改动执行 `npm run typecheck`。模块入口、页 ID、身份和资源引用按改动范围检查；涉及新模块注册、打包或资源发布时补充相应构建检查。页序或双入口变化时核对大纲与实际入口的对应关系。保留已确认内容与实现边界，不顺带修改无关课程或公共组件。

### 页面渲染与边界

确认页面能加载，实际页 ID 与目标一致，逻辑画布为 1600×900；等比例缩放后的显示尺寸不作为逻辑画布错误。检查元素越出画布和容器内部的文字、内容溢出，两者分别记录。

有意设计的代码区、列表等内部视口与整页内容溢出区分。例外须明确用途、可追踪，且视口本身不能越出画布。不允许通过裁切或横向滚动掩盖本应完整展示的内容。

检查默认状态与受影响的关键操作状态。获取并实际打开真实页面截图，核对脚本难以可靠判断的遮挡、字形截断、异常加载和内容错误；查看截图不要求打分。设计图不能替代实现截图。

### 字数与明确限制

每个被检查页面、每个被检查状态都须输出字数及统计口径。`capture.slides` 返回当前状态的 DOM 字符统计：中文、英文字母、数字、标点各按一个非空白 Unicode 码点计数，空白不计；文本节点只遍历一次，隐藏文本和画布外播放器、讲稿不计；可见文本输入值和选中项单列并计入总数。密码及非文本控件不计。

此口径不是 OCR，也不等于完整页面的精确字数：图片、Canvas、视频和 CSS 生成文字未覆盖，输入框值可能包含被裁切部分，具体限制随结果返回。默认状态与操作后状态分别统计，不相加。`analyze.pages` 的源码近似统计仅作补充，不能冒充当前渲染统计；日常检查不要求生成 HTML 报告。

有用户或项目明确上限时，通过 `--max-chars` 按该口径筛查；任务另有计数口径时单独核对并注明。没有上限时照常报告数量，不自行设置统一门槛或判定超限，不因字多自动删减已确认内容。缺少结果、无法匹配页 ID 或仅有无法读取文字的媒体页面，标记未验证，不记为零字或通过。未覆盖文字涉及明确上限时，须补充人工核对，不能只凭 DOM 计数判定完整内容符合限制。

### 相关交互与内容

实际验证本次涉及的核心操作、重置及必要的等待、失败等分支，核对输入、图形、数值、公式和反馈是否对应。能复算的数据优先复算，明显事实错误须处理。截图不能单独证明交互行为正确；无法执行或缺少证据时标记未验证。

## 工具与覆盖范围

从仓库根目录调用已有入口，按本次改动选择；完整参数与环境准备见[工具索引](../tools.md)，无需在每次检查中重复运行所有命令。

| 工具 | 覆盖范围与限制 |
|---|---|
| `check.module` | 元数据、页 ID、身份及字面量入口、资源引用；动态表达式仍需实测。身份变化补充 `module.identity --check`。 |
| `check.course` | 大纲、PPT 与 Guide 的实际页序、标题及讲稿对应；不存在的入口按任务说明不适用，无法读取的应标记未验证。 |
| `capture.slides` | 复用页面就绪检查、真实截图及 `--actions` 动作；每页状态的 `checks` 返回边界、字数、警告和覆盖限制。截图与字数仍需核对。 |
| `check.bounds` | 通过已有 Chromium 调试会话检查新开页面的默认状态；验证就绪与页 ID，返回相同的边界、字数口径。交互状态优先复用 `capture.slides`，不另设动作格式。 |
| `analyze.pages` | 可选的离线源码近似统计与分布报告；不证明当前状态。 |

日常页面检查可使用：

```powershell
python creator-skill/scripts/tools.py capture.slides --module <模块名> --slide <页ID>
```

关键状态沿用同一命令的 `--actions <动作JSON> --state <状态名>`；仅明确存在字数上限时添加 `--max-chars <上限>`。动作只能覆盖任务已授权的操作。产物保存在模块 `_scratchpad/`；读取截图并核对交互后再形成结论。

几何脚本检查容器滚动尺寸与元素矩形，不能证明不存在遮挡或所有字形截断。未声明例外的裁切、滚动容器发生尺寸超限时报告错误；`overflow: visible` 的尺寸超出和字体边缘可能来自正常排版，单列风险警告，结合截图判断。`data-ppt-viewport="用途说明"` 仅用于真实内部裁切/滚动视口，脚本输出对应例外；不得给整张画布加例外，也不得把本应完整展示的正文标作例外。例外不豁免视口内其他容器的裁切错误。省略字数阈值时，结果中的 `maximum` 与 `exceeded` 为 `null`。

## 修复、结束与受阻处理

按“检查 → 定位问题 → 局部修复 → 复查受影响项”推进。问题写明页 ID、状态、元素、实际表现及判断依据。警告属于启发式风险提示，与确定性错误分列，不能将风险数量当作违规数量。

| 结果 | 含义 |
|---|---|
| 通过 | 已执行且满足对应要求。脚本通过仅覆盖它实际检查的部分。 |
| 不通过 | 已发现明确违规。 |
| 未验证 | 缺少执行条件、证据或工具覆盖。 |
| 不适用 | 当前任务不存在该检查对象，并说明原因。 |

CLI 退出码 `0` 表示已执行工具范围内通过，`1` 表示发现违规，`2` 表示执行错误或存在未验证项；同时读取 JSON 的状态、错误和覆盖限制。浏览器、服务或依赖缺失时先诊断与修复，不能自动免检；仍受阻时说明缺少的条件、未验证范围和下一步。

必需项通过后展示真实效果，按当前 Workflow 进入用户验收。必需项不通过或未验证时明确剩余问题，不声称全部通过。同一问题反复修复无进展时停止盲目重试并说明阻碍，不用固定返工次数代替完成标准。用户后续修改不受自检轮数限制。

默认简短说明检查范围、结果和剩余问题，不强制生成 HTML、评分表或过程文档。
