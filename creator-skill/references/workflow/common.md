# 流程共用说明

供从零创作与参考改编共用。具体制作顺序、设计图、确认节点和制作批次由各 Workflow 管理，本文件只规定如何接续任务、界定确认范围和控制修改影响。

## 续作与局部修改

- 继续制作、修改或修复已有模块时，沿用原 Workflow，不另设续作模式。
- 读取最新大纲、相关页面与对话中的确认记录，判断当前页处于待设计、待设计确认、待实现、待验收或已完成中的哪个阶段，再从该阶段继续。
- 按根入口的产物约定检查当前模块 `_scratchpad/` 中可复用的原稿提取、设计图与检查证据；文件存在不代表用户已确认，也不代表对应最新实现。
- 复用仍然有效的大纲、设计、代码和确认；不能凭已有 React 文件、图片或可运行页面推断用户已经认可。
- 原 Workflow 或当前确认状态不明确时，先检查已有材料；只有缺失信息会影响下一步是否可以执行时，才澄清具体问题，不要求重新确认全部内容。
- 局部修改只处理指定页面及必要依赖，检查相关交互、前后衔接和页序，保留未受影响的已确认成果。大纲增删改与重排见[大纲与页面变更](../design/course-outline.md#大纲与页面变更)。

## 设计、实现与确认

设计图用于确认预期效果，真实页面用于检查实现结果，两者不能互相替代。

是否生成设计图、何时等待用户确认、按页还是按批次推进，由当前 Workflow 和用户明确要求决定。从零创作按其逐页确认流程执行，不能仅因智能体认为方向清楚或实现简单而省略确认。

确认只覆盖用户实际认可的版本和范围。相关目标、内容或设计发生实质变化后，重新确认受影响部分；未受影响的确认继续有效。

用户明确要求跳过某一步或改变制作批次时，按指定范围执行，不将一次例外扩展为整份演示的默认规则。

## 自检与用户验收

页面制作与修改后执行[基础检查与验收](../eval/checks.md)，按改动范围选择适用项；必须查看真实截图并验证相关交互，无需默认打分。仅在用户明确要求评分时加载 Rubric；普通检查或优化请求不自动触发评分。

自检完成后按当前 Workflow 进入用户验收；自检通过不代表用户已经认可。用户提出的新修改继续按影响范围处理，不受自检返工轮数限制。
