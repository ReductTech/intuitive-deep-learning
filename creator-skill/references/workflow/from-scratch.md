# 从零创作

适用于从主题、目标、对话、文字或论文等材料开始创作演示。

先与用户反复讨论并确认大纲，再按页完成“视觉设计图 → 用户确认 → React 实现与自检 → 用户验收”。当前页验收后，才开始下一页。用户明确改变流程时，按其指定范围执行。

## 1. 讨论并确认大纲

了解演示目的、受众基础、材料范围和时长。根据已有信息提出可讨论的大纲，不要求用户先填完整需求表。

与用户讨论内容取舍、展开顺序和页面划分，持续修改 `modules/<模块目录名>/outlines.json`。每页明确主要目标、核心内容及与前后页的关系；文件结构与维护方式见[大纲说明](../design/course-outline.md)。

- 讨论中主动给出组织建议，并说明影响主线的取舍。
- 用户提出问题或修改意见时，继续讨论和调整，不急于开始制作。
- 用户确认大纲或明确要求按当前大纲开始制作后，进入第一页。
- 大纲确认前，不生成页面视觉设计图或编写页面实现。
- 大纲确认后仍可调整，处理方式见[大纲与页面变更](../design/course-outline.md#大纲与页面变更)。

## 2. 生成当前页视觉设计图

读取当前页大纲、必要的前后页以及已有确认的页面，明确本页要让观众理解什么，再决定如何呈现。

阅读[页面设计指导](../design/design.md)，使用图像生成工具生成当前页的视觉设计图，展示预期的页面内容与构图。设计遵守根入口的画布、文字与共享组件约束。

设计图保存到当前模块的 `_scratchpad/`。工具无法直接指定保存位置时，将返回的文件归档到该目录后展示，并保留页 ID 与版本的对应关系。

- 设计图应体现主要内容、视觉主体、信息层级和必要的操作入口。
- 有交互时，简短说明操作对象、操作后的变化及其解释作用；一张静态图不必展示所有状态。
- 沿用已确认的整体风格，同时根据本页内容选择构图，不机械复制上一页。
- 展示设计图，并用简短文字说明本页目标与关键交互，等待用户确认。
- 用户要求修改时，调整设计并重新展示，直至确认。
- 工具不可用时说明阻碍，不用文字描述冒充设计图，也不自行跳过确认开始实现。

此阶段不编写本页 React 实现。设计图中的事实、公式和数值仍需核对，不能因图片已经生成就视为正确。

## 3. 实现并自检当前页

用户确认当前设计图后，依据该版本实现 React 页面。工程要求见[工程实现](../engineering/implementation.md)。

- 保持已确认的内容、构图和交互意图；文字、公式和图表用适当的组件实现。
- 不将整张设计图作为页面背景来代替正式实现。
- 若实现中发现设计存在事实错误或无法合理实现的部分，说明问题和调整建议；涉及主要内容、构图或交互变化时，先让用户确认。
- 按[基础检查与验收](../eval/checks.md)检查真实渲染、字数、相关交互和工程约束，修复并复查；仅用户明确要求时执行 Rubric 评分。
- 自检完成后，展示真实实现效果，并提供可查看或操作的入口，等待用户验收。

自检通过不等于用户已经验收。不得用设计图代替实现效果，也不得在等待验收期间自行制作下一页。

## 4. 修改或进入下一页

用户提出修改意见时，继续处理当前页。

- 文字、间距、颜色或局部行为等明确修改，可直接实现、自检并重新展示。
- 核心内容、主要构图或交互方式需要重做时，返回视觉设计图阶段。
- 用户确认当前页没有问题或明确要求继续下一页后，按最新大纲进入下一页。
- 当前页内容确认只适用于当前页，不自动表示后续页面也已获准实现。

按上述方式逐页推进，直至完成最新大纲中的页面。

## 中断后继续

按[续作与局部修改](common.md#续作与局部修改)核对当前页进度，继续本 Workflow 的设计确认、实现与用户验收，不因已有代码而跳过尚未完成的步骤。

## 整体收尾

全部页面逐页验收后，通看整份演示，检查页序、内容衔接、视觉一致性，以及大纲与实现是否对应。

展示整体验收结果，询问用户是否还有需要调整的地方；有反馈时按影响范围继续修改。用户确认结束后，简要说明完成情况与仍存在的限制，不主动追加页面或扩展任务。
