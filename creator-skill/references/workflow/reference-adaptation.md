# 参考改编

适用于根据既有 PPT、PDF 或逐页截图制作 React 演示。先获取逐页截图和文本，形成对应大纲，再逐页复刻、优化与验收。共用原则见[流程共用说明](common.md)。

## 1. 提取并理解原稿

使用截图与文本提取工具获取各页内容，保留原始页序，建立原页码、截图和文本的对应关系。

先确定目标模块，必要时用 `module.init` 创建初始大纲。PPTX 使用 `extract.pptx --module <模块目录名>` 一次提取逐页图片、正文和演讲者备注到该模块的 `_scratchpad/`，调用方式见[原稿提取](../tools.md#pptx-原稿提取)。PDF 等原稿的提取结果也放在此处。备注作为理解讲述意图的材料，与页面正文区分。

- 查看全部页面，理解演示主线、内容结构和前后衔接。
- 截图用于识别构图、配色、素材、视觉层级和图表关系；文本用于核对标题、正文、数据与公式，两者相互补充。
- 检查图表、公式和图片中的信息，补充提取遗漏；关键内容无法辨认时向用户确认，不猜测补齐。

## 2. 确定改编范围与大纲

根据用户要求确定保留和调整范围。未指定时，默认保留原稿的内容、页序和主要视觉表达，允许局部优化及有明确表达价值的交互改进。

| 用户要求   | 处理方式                                           |
| ---------- | -------------------------------------------------- |
| 忠实复刻   | 保留指定的版式、配色、素材与图表关系，只做必要适配 |
| 参考借鉴   | 保留核心内容及适用的表达方式，根据当前需求重新设计 |
| 整体重设计 | 在约定范围内调整叙事、构图和交互                   |
| 局部修改   | 只处理指定部分及必要依赖，保留其他已认可内容       |

简短说明关键取舍；只有不确定性会实质改变结果时才询问，沿用已有确认。

维护 `modules/<模块目录名>/outlines.json`，具体结构见[大纲说明](../design/course-outline.md)。

- 默认每个条目对应原稿一页，必须记录稳定页面 `id`、题目 `title` 与演讲稿 `snippet`，不增加其他页面字段；缺少讲稿时不自行补写。
- 大纲与原页码、截图的对应关系记录在模块 `_scratchpad/`。
- 不在提取阶段擅自删减、拆并或重排页面；需要调整时说明理由，按用户确认的范围执行。
- 忠实复刻也不继承事实或计算错误，发现问题时说明并提出修正。
- 大纲与改编范围确认后开始逐页制作；已有明确确认时直接沿用。

## 3. 设计当前页

同时查看当前页截图、文本和大纲，必要时查看前后页，明确本页目标及原稿如何表达这一目标。

原稿截图作为默认设计依据，不重复生成视觉设计图。保留适用的构图、视觉层级、关键素材和图表关系，优化文字过小、对齐不齐、间距不当、图片模糊或内容拥挤等问题。

判断交互能否帮助观众观察变化、比较结果、理解过程或验证判断。适合时提出交互改进，不适合时保持静态。

- 明确操作改变什么、观众看到什么，以及变化如何帮助理解。
- 保持图形、数值、公式和解释一致，不添加只有外观变化的控件。
- 大幅改变主要构图、核心内容或交互方式时，先展示调整方案并等待确认；需要视觉预览时使用图像生成工具。
- 局部优化可直接实施，不因个人审美将原稿改成另一套设计。

页面构图、视觉取舍和交互统一按[页面设计指导](../design/design.md)处理。

## 4. 实现、自检与用户验收

按原稿及已确认的调整方案实现当前页，工程要求见[工程实现](../engineering/implementation.md)。

- 文字、公式和图表使用适当组件实现，不将整页截图作为正式页面。
- 尽量提取复用原稿素材，不无故替换或重新生成。
- 按[基础检查与验收](../eval/checks.md)检查真实渲染、字数和相关交互，并与原稿对照，修复并复查遗漏、误写、布局和行为问题；仅用户明确要求时执行 Rubric 评分。
- 自检后展示真实实现效果及可查看或操作的入口，等待用户验收。
- 用户提出局部修改时，直接修改、复验并重新展示；涉及主要设计变化时返回设计阶段。
- 当前页确认后再进入下一页；用户明确授权连续制作时，按授权范围推进，仍逐页自检。

## 5. 处理变更与整体收尾

大纲与页面调整按[大纲与页面变更](../design/course-outline.md#大纲与页面变更)处理；涉及改编范围变化时，重新核对受影响页面与原稿的保留要求。

中断后继续或修改已有页面时，按[续作与局部修改](common.md#续作与局部修改)定位当前阶段，沿用本 Workflow 的原稿约束与验收方式。

全部页面完成后，核对原稿、大纲和实际页面的对应关系，检查内容完整性、页序、衔接与视觉一致性。向用户展示整体结果，处理后续反馈，确认结束后简要说明完成情况与剩余限制。
