# Workflow A：参考改编

适用于用户提供既有 PPT，并要求转换、借鉴、修改或重新设计的任务。共用执行原则见[流程共用说明](common.md)。

**理解原稿 → 明确保留与调整范围 → 组织页面内容 → 设计页面 → React 实现 → 评估与修正**

1. **理解原稿**
   阅读可用的 PPT、PDF、逐页截图或扫描页及配套材料，识别页数、尺寸、内容结构、页面顺序、核心信息、视觉特征、图表关系与潜在交互。检查事实、公式、因果关系、图片质量、阅读顺序和画布容纳情况。

2. **明确改编范围**
   按用户意图确定处理方式：

   | 用户意图 | 处理范围 |
   |---|---|
   | 忠实转换、复刻原稿、保持版式 | 保留指定的页序、版式、配色、图片和图表关系，只做必要的 React 与画布适配 |
   | 参考、借鉴 | 提取核心内容、表达关系和局部视觉意图，再根据当前需求设计 |
   | 重新设计 | 可以重组叙事、版式与交互，说明关键取舍，按已有授权推进 |
   | 混合请求 | 按用户指定分别保留和重做，不推翻已认可的其他部分 |

   简短说明“保留什么、调整什么、为什么”。意图未说明时先检查材料，只有不确定性会实质改变结果时才澄清；沿用已有确认，不重复询问。

   忠实转换不继承事实错误。发现错误、适配冲突或无法保留的效果时明确说明，不以“提高质量”为由自行重做整套排版。

3. **组织页面内容**
   建立原稿与新页面之间的对应关系。忠实转换默认保留原页序；拆分、合并、重排或新增页面应符合用户指定范围，并说明必要的调整理由。不得将整体重设计默认为可以随意改变原稿内容。

   材料较多时先建立总页序和转换范围，不因已读完整套 PPT 就同时实现所有页。页数由材料范围和表达需要决定，不设固定配额。

4. **设计页面**
   在满足内容要求的前提下，优化信息层级、页面构图、视觉表达和必要的交互。借鉴原稿不意味着必须复制其缺陷；原稿视觉与当前组件体系的取舍应符合改编范围。

   是否生成设计图、逐页确认或连续制作，遵循用户要求、已有授权与共用执行原则。已认可的预览不重复生成；对已认可页面的局部修复不重新触发整套设计流程。

5. **React 实现**
   根据确定的设计和工程约束完成实现，优先复用适用的现有组件和基础设施。只有语义评价、开放生成或较重计算确有需要时，才考虑相应模型能力，不为流程完整而接入 AI、GPU 或启动服务。

6. **评估与修正**
   检查内容是否完整、原稿约束是否满足、页面是否正确呈现，以及交互和工程行为是否符合预期。逐页核对实际渲染与受影响状态；连续制作也不省略验证。

大纲维护见[大纲说明](../design/course-outline.md)，实现与验收分别见[工程实现](../engineering/implementation.md)和[评估说明](../eval/evaluation.md)。按当前阶段选读。
