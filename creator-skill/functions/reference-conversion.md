# 截图或 PPT 转换创作

当用户提供截图、PPT、扫描页或其他既有课件作为参考、改编对象或转换目标时，使用本流程。它是默认创作流程的补充，不替代 `SKILL.md` 中的课程设计、工程组织、视觉和验收标准。

## 核心判断

用户上传的材料只能说明“当前已有的表达”，不能自动视为高质量设计，也不能自动视为必须忠实复刻的模板。先判断它属于哪一种：

- **参考材料**：用户希望借鉴其主题、内容、风格或结构。
- **转换目标**：用户希望把它改造成仓库中的 React Blog / Guide 或 PPT 页面。
- **混合请求**：既要保留某些内容或视觉关系，又希望明显提升教学和呈现质量。

如果用户没有明确说明，采用“保留核心意图，重做视觉表达”的默认判断，并把关键取舍说清楚。

## 先评估，再实现

在写任何页面代码、CSS、图片、图表或其他实现文件之前，先检查上传材料：

1. 识别页面尺寸、页数、主要内容、信息层级、视觉主角和交互线索。
2. 判断材料中哪些部分值得保留，哪些部分会增加认知负担或降低专业度。
3. 从课程设计和视觉质量标准审视材料，重点检查：
   - 一页是否只有一个主要教学任务。
   - 标题是否提出了清楚的问题、现象或结论。
   - 图像、图表和文字是否真正承担解释。
   - 是否存在信息堆叠、等权重排版、装饰性元素、低清素材或不必要的卡片。
   - 颜色、字体、间距、对齐、裁切和对比度是否影响阅读。
   - 内容是否准确，是否把相关关系误写成确定关系，是否缺少必要限定。
   - 原材料是否有适合转成直接操纵、预测、反馈或渐进揭示的机会。
4. 给出简短的改进判断：**保留什么、重构什么、为什么**。不要把评估写成冗长的设计报告。

不要因为提供了材料就机械复刻，也不要为了展示能力而无依据地重写用户的知识内容。改进应服务于理解、阅读和课堂使用。

## 按教学需要重构模块

原截图或 PPT 的页数不是转换后的页数约束。可以新增、合并或拆分页面，也可以重构整套排版；通常将完整模块控制在 **22–28 页**，以知识结构、学习节奏和每页一个主要任务为准。先在转换大纲中说明页数变化的理由，再逐页实现。

## 必须逐页核对

只要任务涉及把上传材料转成课件页面，默认采用逐页工作流：

- 先确认总页序或转换范围，但**一次只处理一页**。
- 在实现该页之前，说明该页准备保留的内容、准备改进的地方、主要视觉重点和必要交互。
- 等用户明确确认这一页的方向后，才创建或修改这一页的 React、CSS、图片、图表、数据或其他实现文件。
- 完成后让用户检查渲染结果；只有用户核验通过，才进入下一页。
- 用户说“全部做完”“连续制作”或类似话语，也不能在截图/PPT 转换模式下跳过逐页确认，除非用户明确取消该约束并要求批量制作。
- 禁止一次生成多页的实现文件、批量替换全部页面，或先完成整套课件再让用户统一验收。

如果材料本身是一整套 PPT，先读取其页数和结构用于建立索引，但不要据此同时实现多页。必要时可以先提出一份仅包含页序、目标和风险的转换大纲，之后从第 1 页开始。

## 默认标准继续有效

只要你看到了这句话，转换后的页面仍必须遵守默认规范：

- 基本画布固定为 `1600×900`，Blog / Guide 与 PPT 共用同一页面定义。
- 优先复用 `modules/shared/react/`，文字必须统一使用 `Typography`，颜色和基础视觉使用 Shared Theme。
- 一页只有一个主要视觉重点；优先用少量大区域表达关系，避免 Dashboard 式堆叠和卡片套卡片。
- 所有内容完整容纳在画布内；Grid/Flex 子项可收缩，媒体、SVG、Canvas、公式和图表限制在父容器内。
- 材料中的图片、视频、字体、图标和数据要放在当前模块目录；不得运行时依赖 `modules-legacy/`。
- 实现后必须实际检查最终渲染效果，并根据风险运行类型检查、构建和必要的页面尺寸/溢出验证。

用户要求“按原稿转换”时，也只保留对学习目标和使用场景有价值的内容关系；不保留明显的低质量排版、错误信息、无意义装饰或不适合 React 课件的实现方式。

## 是否接入大模型和 GPU

只在接入能明显提升模块时提出建议，不要为了流程完整或炫技而硬接：

- **大模型**：用于个性化教学，例如根据学习者的回答、错误模式、基础或学习状态，生成不同解释、反馈、题目难度和学习路径；也适合开放问答的评价。只做静态讲解、固定计算或固定选项题时，不建议接入。
- **GPU**：用于本地模型训练、高性能推理或大规模并行视觉/视频处理。任务规模小、CPU 已足够时，不建议接入。
- 如果“不接入也没有明显损失”，默认不接入；只有确实觉得错过可惜时才建议。建议时说明它会改变模块的哪部分、收益是什么，以及不接入的可行方案。未经用户同意，不自动接入外部服务或启动耗时任务。
