# 课程创作

把用户给出的主题、问题、材料、数据、图片、代码、参考风格或改动要求，变成一次可追踪的理解变化。输入不一定是“材料”；先提取对象、关系、受众、目标、证据、约束和交付物，只追问会改变方向的问题，其余假设保持可回溯。用户指定的重点、页数、风格、素材和交付形式优先；教学判断只填补空缺，不覆盖这些约束。小改沿用已有语境。

## 创作立场

课程不是把信息铺满页面，而是校准学习者对一个对象的模型：先让已有直觉暴露，再让预期与证据发生差距，随后用术语、公式或机制压缩刚刚看见的关系，最后在变化条件下调用它。先问“学习者必须改变什么判断，才会觉得新概念有必要”，再决定讲什么、画什么和是否交互。材料已经有清晰论证时，不为了热闹强行游戏化。

## 设计判断

- 用认知动作组织课程，而不是用知识点、卡片或固定幕数：情境/初始模型 → 未决问题 → 观察、预测或操作 → 可比较证据与中间因果 → 概念命名或形式化 → 反事实、应用或迁移 → 回扣开场与边界。这个弧线可以合并、压缩、倒置或省略；每次转折都必须有认知理由。
- 每页（或一段连续动作）只承担一个主要转折：学习者此刻要看见、预测、区分、解释、修正或决定什么？哪条证据能支持或推翻它？上一页为何使下一页成为必要？“完成”指能指出依据、预测变化、解释原因或判断边界，不是看过或偶然答对。
- 把同一对象在现实情境、动作、数据、图表、公式、代码和决策之间的变化说清楚：什么保持不变，增加了什么，舍弃了什么。图、词、符号必须能互相回指；不能用并排表征制造信息堆叠。
- 交互是认知仪器，不是装饰。只有能让学习者预测、操纵、比较、检索、解释或修正时才需要交互；一次先改变承担解释责任的变量，保留前态、参照和操作痕迹。反馈贴回原对象，指出证据与失效推理，错误可重试；自由度随问题需要释放，不按页面空间预先塞满控件。
- 例子要显出不变量、代价和边界。迁移至少改变情境、表征、约束或目标之一，并要求说明仍成立的关系、失效条件和不确定性；只换数字不算迁移。区分来源事实、观测、模型假设、教学简化和设计推断，真实、生成或重绘素材标明性质与来源。

## 交付契约

PPT 是第一产物，逻辑画布必须且只能为 1600×900 px；先用同一语义事实源完成 PPT，再把它直接转换为 blog/Guide。转换只是把空间关系改成阅读时间流，保留页面顺序、标题、证据、公式、例子、结论、反馈和页间问题，不另创一套课程。前后页关联、UI Kit 交互与可访问性、模块资源边界和完成检查是硬约束；版式、媒介、页数、隐喻和是否交互由当前知识关系决定。默认大标题模板位于 modules/shared/templates/default/。

流程反馈遵守现有 UI Kit 的语义边界：无按钮或控件承载学习动作时，使用 UI Kit 的“下拉提示”流程让学习者确认进入下一阶段；按钮或其他控件完成动作时，使用 UI Kit 的“直接弹出”流程。Select 只表示真实的互斥选择，ExplainPanelButton 只表示邻近解释，结果与错误回到原对象；禁止另造 modal、全局 toast、悬停独占解释或第二套提示系统。

## 禁止

不要定义开路、答案先行、把图当插图或把控件操作当理解；不要同时改变多个关键条件却称为比较；不要让动画、滚动或装饰制造空白并替代证据；不要把反馈压成“正确/错误”、把相关说成因果、把示意说成事实、把隐喻当机制；不要把一次答对、重做原题或只换数字称为掌握；不要让 PPT 与 blog/Guide 各自增删知识；不要从 modules-legacy 引入运行时代码或资源。

## PPT-first 工作流

1. 从用户输入归一出学习对象、初始直觉、关键障碍、可观察证据和页间问题。
2. 先完成固定 1600×900 PPT：让主证据可见、前态可比、每页转折有理由。
3. 在 PPT 中实现必要的操作和反馈，验证它们确实改变判断。
4. 从同一语义定义直接转换 blog/Guide，只重排空间为阅读流。
5. 复查边界、事实性质、前后页关联、迁移条件和交互反馈位置。
