# 远程课程目录与部署

## 数据流

`原仓库 develop → reduct-shuku/intuitive-deep-learning/main → 固定课程快照 → MySQL 目录 → 首页`

- 原仓库仍是课程编辑入口；独立仓库负责分发。
- `course-library.lock.json` 固定本次部署使用的提交。
- 后端启动时校验快照的 Git 状态、仓库、提交和课程标识，一次性登记 `shuku_library_courses`。请求页面时只查数据库，不请求 GitHub、不重新扫描目录。
- 首页统一调用 `GET /api/shuku/public/courses`。前端内置模块只负责渲染，不再决定线上展示哪些课程。只有专门的 `preview` 开发模式保留本地目录。
- 来源、标题、简介、分类、难度、封面和页数取自快照中的清单与 `outlines.json`。无分类时沿用课程 badge。

## 两类记录

| 类型 | 存储 | 学习入口 |
|---|---|---|
| 远程原生课程 | `shuku_library_courses`，主键为课程 UUID + 快照提交 | `module:<alias>`，由本次部署的课程组件渲染 |
| 用户在术库发布的课程 | 原有课程、修订、审核和发布表 | `course:<UUID>`，读取对应修订的构建文件 |

目录接口中，远程原生课程带 `kind: library`、`alias`、`module_id`、`source_commit`、`github_url`、`cover_url`、`page_count`；`version` 是提交号缩写。原有已发布课程字段保持兼容，仍包含 `revision_id`。

`GET /api/shuku/public/library/<alias>` 返回已登记的原生课程详情。未登记的本地模块不能仅凭前端路由出现在课程详情中。

原生课程的来源提交不等于术库审核后的正式发布版本。本次不伪造创建者、审核或贡献记录，不自动将原生课程绑定给某个测试账号；已有原生课程的共创/反馈限制保持原状。用户发布的独立课程即便使用相同原生模块，也不会覆盖源课程。

## 更新与回退

1. 上游变动先由现有同步工作流写入独立仓库 main。
2. 部署人员执行 `npm run courses:fetch -- --latest`，获取固定快照并更新锁文件。
3. 使用 `IDL_COURSE_LIBRARY_ROOT=locked` 构建前端；后端 `SHUKU_COURSE_ROOT` 指向同一 `.course-library/<commit>` 目录。
4. 首次升级使用迁移账号执行 `python -m shuku_backend migrate`，增加目录表；运行账号不执行建表。
5. 部署前端并重启后端。启动时登记相应快照，目录才切换到本次部署版本。

远程 main 更新不会直接切换线上课程；新增 TSX 必须先构建部署，防止目录先更新而页面尚不存在。同步失败会终止启动并保留上次部署，目录接口失败时前端明确显示错误，不偷偷回退本地列表。

旧快照的目录记录保留。回退时同时恢复前端、锁文件和 `SHUKU_COURSE_ROOT`；不删除用户业务数据。数据库升级是可重复的增量升级，保留原有基线校验，新增 `002_remote_course_catalog` 标记。

## 验证

- MySQL 测试覆盖登记、重复同步、更新与历史保留、污染/错误快照拒绝、部署提交匹配、显式迁移和重复迁移。
- 浏览器测试覆盖目录只展示 API 结果、空目录与接口故障不会回退本地课程、原生详情和原有发布版本/反馈流程。
- TypeScript、独立课程生产构建和课程导入来源检查均需通过。
