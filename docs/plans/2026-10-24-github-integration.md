# T07 GitHub 对接实施计划

目标：在独立 `shuku_backend` 中接通真实 GitHub，并保留现有编辑器和站内审核流程。

1. 同步 develop，核对原模块边界和 Demo App 配置；保留用户已有文档改动。
2. 实现 App JWT／安装令牌、固定 GitHub 主机、拒绝重定向、请求超时及安全错误码。
3. 新增仓库、修订映射、外部 PR、Webhook 投递和持久操作记录。
4. 接入私有仓库创建、差量 PR、远程合并核验、Tag／Release；外部结果核验后才提交本地正式状态。
5. 接入分支清理、上下架／删除、Issue、Webhook、周期校准和失败重试。
6. 页面增加默认收起的同步详情；外部 PR 通知与待审核入口复用现有页面。
7. 自动测试逐步验证，再在独立仓库验证真实链路；回归原有功能、构建，更新进度并推送 GitHub。

关键决定：

- 不复制原 Node 后端，不改 `idl_backend`，复用既有任务／存储／审核服务。
- GitHub 尚未配置时保留本地演示；已绑定远程的课程必须经过真实核验。
- 固定最初基础提交，拒绝把官方后来的修改混入本次贡献；不强推覆盖。
- 审核分支清理独立重试；不因清理失败回滚已确认的合并或正式版。
- 任意外部脚本不自动执行或公开。外部 PR 远程合并和课程正式发布保持独立。
- 原 App 公网回调不切换；新服务公网转发在部署阶段验证。

详细实现和恢复方法见 `docs/shuku-github-integration.md`。
