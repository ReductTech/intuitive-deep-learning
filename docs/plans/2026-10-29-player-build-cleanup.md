# 播放器构建回收与重试

沿用 `run_build()` 执行普通构建和播放器构建，不增加内存或延长 90 秒构建时限。

1. 构建前验证任务；Node 启动独立进程组，esbuild 留在同组。编译环境不传入数据库和 GitHub 凭证。
2. 独立监控构建截止时间和续期截止时间；续期阻塞也会终止构建。续期预算 20 秒，短于任务租约 30 秒。
3. 所有退出路径都终止进程组，等待父进程和组内仍在执行的后代退出，再返回或抛出异常。回收不能确认时标记 `BUILD_CLEANUP_FAILED`，禁止自动和网页重试，交由管理员确认处理。
4. 播放器状态区分超时、源码错误、任务失效和续期失败。已登录且有课程访问权限的用户可重试失败的同一播放器任务；操作幂等，不创建课程修订，也不修改审核、版本或发布记录。
5. 编辑预览和学习页面共用状态及重试逻辑。发布产物仍使用原有不可变校验与任务租约校验。

验证：Linux 父子进程超时、心跳失败与阻塞、父进程先退出、连续重试不重叠、回收失败停止重试；数据库任务幂等、权限、同源保护和正式版不变；浏览器失败提示、重试成功与禁止重试。

部署先停止原服务并确认其进程组／服务控制组内旧构建全部退出，再启动新代码，最后重试失败的播放器任务。测试和操作均不删除或重新发布课程。
