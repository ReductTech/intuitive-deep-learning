# 课程仓库分离实施计划

**目标：** reduct-shuku/intuitive-deep-learning 的 main 作为课程分发仓库，旧 main 改名为 back；编辑源保持 ReductTech/intuitive-deep-learning/develop。

**架构：** 单向同步已提交的 modules、assets 和 creator-skill，记录来源提交与文件哈希，不反向合并代码。平台通过可配置、固定提交的本地课程快照加载课程，共享业务后端和计算 API 不复制到课程仓库。

**技术：** Python 标准库、Git、GitHub Actions、Vite 路径适配、现有 Python 课程构建。

1. 编写导出器及测试：仅导出许可路径；保护独立改动，不复制未提交文件、凭证、平台后端；本轮仅新增和修改，不自动删除历史课程文件。
2. 目标仓库定时检查上游，课程变更后同步，无需跨仓库长期 Token；同时保留手动触发。保护分支、禁止强推。
3. 梳理共享组件、UUID 素材、创作规范和计算 API 依赖；生成分发清单与来源锁。
4. 增加前端和后端课程根目录配置，以及固定提交的拉取工具；默认模式兼容原目录。配置了独立仓库时缺失快照应报错，不静默回退。
5. 验证导出幂等、冲突、素材、前端构建、后端目录与本人预览、GitHub 自动同步；按用户要求备份旧 main 为 back，再发布新 main。
6. 切换 Demo 使用独立课程快照，验证后推送原仓库 develop，记录两端提交与仍存在的平台服务依赖。

## 边界与恢复

课程源码更新需要重新构建前端，原生 TSX 不在浏览器直接执行 GitHub 文件。预览构建读取相同固定快照。切换失败恢复上一静态发布和课程根目录，不修改数据库。目标独立改动会导致同步停止并报错，不能静默覆盖。

原始课程目录依然保留为编辑源。真正拆分的是分发与加载边界，课程依赖的计算和登录等 API 仍由平台提供。GitHub 定时任务按约五分钟检查，实际启动时间受平台调度影响。
