# 从 shukuDemo_server 迁移到 intuitive-deep-learning 的业务范围

确认日期：2026-10-23。本文依据本次用户指定范围，确定后续迁移做什么、不做什么及完成标准；**本文不是迁移完成报告，本次不修改业务功能或部署服务。**

## 1. 最终产品与迁移原则

最终部署和持续维护的产品是 **intuitive-deep-learning**。`shukuDemo_server` 是梳理业务逻辑的 Demo 和迁移参考，最终运行不依赖它的服务、页面、数据库接口或部署目录，也不形成两个产品之间的长期同步系统。

迁移对象是审核、归属、权限、共创、发布、治理、贡献、反馈、个人记录、接口、任务及持久化的业务规则和必要数据模型。按 intuitive-deep-learning 的现有前后端组织实现，不整包复制 Demo，也不因为 Demo 使用 Node.js 就新增一套必须长期维护的 Node.js 平台后端。

- 现有 React 课程、术库/PPT、编辑工作区、生成能力、预览、训练与问答服务继续保留，由当前项目负责。
- 不迁移 Demo 的多来源课程接入、在线编辑和预览实现。审核与发布从当前编辑器交付的课程修订开始，接入点另见第 5 节。
- 用户身份和课程身份均使用稳定标识；页面标题、目录名、GitHub 用户名不能当作权限或归属依据。
- PostgreSQL 保存主业务关系和业务状态；课程源码、图片、视频及可播放文件保存在本地文件桶，数据库不保存文件正文 `bytea`。
- GitHub 相关的 PR、SHA 核验、合并确认及分支安全规则属于相应业务迁移范围；实际调用由新产品后端承担，不回调 Demo 完成操作。
- 保留现有计算、缓存、遥测服务的职责，不把已有实验缓存一并强行改库。本范围不等于必须把整个系统所有数据都放进 PostgreSQL。

目标仓库核对基线：`39a05579aa455c15edb2f59441d0af536cbe23f7`。Demo 参考基线：`fae5abd0c23ac15f1508f0b8aa0970bf2c83b268`。参考版本之后的变化需另行核对，不能自动视为已经迁移。

## 2. 确定迁移的业务逻辑

下表的 M01～M13 均在迁移范围内。“来源入口”是 Demo 仓库中的定位线索，不表示照搬文件或保持同名接口。

| 编号 | 业务范围 | 必须保留的规则与行为 | Demo 来源入口 |
| --- | --- | --- | --- |
| M01 | 统一审核机制 | 提交、待审核、通过、退回、重提；审核绑定不可变修订及内容摘要/SHA；内容变化使旧批准失效；保存审核意见、审核人和时间；服务端阻止绕过审核发布 | `collaboration.js`、`storage/postgres-commands.js`、`storage/postgres-github.js` |
| M02 | 用户、课程归属与角色 | 稳定用户身份、课程作者/所有者、课程管理者及平台管理员；学习者权限；每次写入检查资源归属和课程授权；身份验证与业务角色分开；GitHub 身份仅用于仓库授权及贡献映射 | `api.js`、`database.js`、`github.js`、`storage/postgres-store.js` |
| M03 | 私有共创与隔离 | 从指定正式版本创建本人工作区，固定基础版本和修订；本人草稿与官方内容隔离；访问权限覆盖元数据、文件和接口；共享仓库/桶内的他人内容不可读取、覆盖或删除 | `collaboration.js` 的 `createPersonalVersion`、`storage/postgres-commands.js`、`storage/postgres-github.js` |
| M04 | 新课程首次审核 | 当前产品创建的课程先保持私有待审核；作者查看进度和意见；管理员针对具体修订审核、退回、重提；通过后才能公开首版；审核期间不得泄露草稿 | `reviewCourseSubmission`、`resubmitCourse`、`submitUploadedCourse` 的业务规则；不迁移其上传入口 |
| M05 | 共创差异审核与评分 | 对比提交版本与基础版本，展示文件/内容差异及真实预览引用；通过或要求修改；评分绑定当前提交，提交变化后旧评分/批准失效；禁止本人审核、评分和合并本人的贡献；并发变化时要求重新核对 | `reviewContribution`、`decideContribution`、`mergeContribution`、`database.js` 的评分与贡献记录 |
| M06 | 合并与正式发布 | 审核、合并、正式发布独立；校验当前修订、目标版本和权限，确认远程合并结果；合并后产生待发布内容；版本级别、说明、固定修订及产物关联；成功后切换正式版本，失败保留旧版；支持历史版本及回滚 | `collaboration.js`、`storage/postgres-github.js`、`github.js` |
| M07 | 目录与课程治理 | 已发布且可见的课程进入目录；搜索、分类、排序、元数据维护；上下架与恢复；本人工作区删除及管理员永久删除；关联记录清理、共享内容保护及失败恢复；管理员下架不能被后台同步自动撤销 | `api.js`、`database.js`、`storage/postgres-business.js`、`storage/postgres-remove.js` |
| M08 | 贡献溯源与排名 | 记录作者、审核者、合并者、发布者；关联修改、PR/SHA、合并事实及进入的正式版本；保留历史署名；按已合并 PR 的有效质量分累计排名，直接提交单独统计；删除个人工作区不抹去官方贡献历史 | `database.js`、`collaboration.js`、`storage/postgres-business.js`、`storage/postgres-auxiliary.js` |
| M09 | 课程反馈与消息 | 问题绑定课程、学习版本及反馈人；处理队列、去重、状态及重试；使用 GitHub 的课程可创建对应 Issue；课程管理者收到消息；未读、分页和已读按接收人隔离，已读不等于问题解决 | `api.js` 的 `CourseErrorReports`、消息接口、`storage/postgres-business.js` |
| M10 | 收藏、学习记录与版本续学 | 收藏、最近学习、具体正式版本及学习方式按账号持久化；跨浏览器继续；新版不强制替换正在学习的旧版；主动切换版本；已下架或不可访问版本明确报错，不偷偷替换成其他版本 | `api.js` 的个人课程库接口、`storage/postgres-store.js`、`lesson-player.js` |
| M11 | 对外课程与贡献接口 | 返回可访问课程、正式版本、固定内容引用、贡献明细和排名；公开读与受权内部读/写分开；错误上报接口复用同一反馈链路；分页、参数校验、调用权限、限流和幂等；不暴露私有草稿或内部凭证 | `api.js`、`storage/postgres-store.js`、`storage/postgres-business.js` |
| M12 | 任务故障恢复与审计 | 持久任务、幂等键及回执、租约/心跳、检查点、有限重试和人工恢复；重启继续；过期执行者不能覆盖接管者；外部请求与数据库事务分开，先保存意图再执行/核验；记录关键业务审计 | `storage/postgres-tasks.js`、`storage/postgres-scheduler.js`、`storage/postgres-webhooks.js`、`storage/postgres-application.js` |
| M13 | PostgreSQL 主业务存储 | 课程、用户关系、工作区、修订、审核、评分、版本、贡献、反馈、消息、收藏、学习记录、任务和审计的权威记录；事务、约束、索引、结构迁移、连接生命周期、受限账号及备份恢复；文件引用关联本地桶 | `storage/postgres-*.js`、`migrations/`、`storage/local-bucket.js` |

M01 是统一规则，M04 与 M05 是两种审核场景，不重复建设三套审核系统。M13 为其他业务提供持久化，不是把旧 `db.json` 整份存成一个 JSONB 字段。

## 3. 不迁移和继续保留的能力

| 项目 | 本次边界 |
| --- | --- |
| 多来源课程接入 | 不迁移 Demo 的 GitHub 地址导入、网页 ZIP 导入、从头创建后 Agent 打包上传等接入流程及其 UI/API；新课程审核直接接当前产品创建的课程 |
| 在线编辑实现 | 不迁移 Demo 的本地 Agent 创作说明、模板补齐、编辑入口或框架；现有编辑器继续负责真实编辑、生成及保存自己的创作内容 |
| 预览与播放器实现 | 不替换现有 React、术库、PPT、预览和演示功能；迁移业务只补权限、固定修订和发布版本的衔接，不复制 Demo 播放器 |
| Demo 页面和服务 | 不复制 `index.html` 页面体系、不要求原 `server.js` 常驻、不保留对 Demo API 的运行依赖；后台能力集成进最终产品 |
| 分阶段登录 | 第一阶段复用共用密码和测试账号登录规则，在新后端跑通会话、权限和业务；后续接入减论 API，停止 Demo 登录。测试账号显式初始化，不复制旧库或开放任意身份切换 |
| Demo 运维配置 | 不迁移 Demo 的 IP、端口、systemd/Nginx、证书、密钥、`.env`、GitHub App 凭证或运行数据目录 |
| 计算与教学内部逻辑 | 不因迁移重写视觉训练、问答、模型服务、页面练习、已有缓存或遥测；页面体验评价不替代贡献审核评分 |
| 演示数据与兼容负担 | 不默认迁移 Demo 用户、课程、旧 JSON 或历史兼容层；确需保留的内容单独列清单，验证归属后导入 |

“不迁移在线编辑和预览”是指保留 intuitive-deep-learning 的实现，并非取消线上编辑或审核预览。当前编辑器的浏览器草稿、本机源码编辑及模拟生成边界见[创作说明](../src/creator/README.md)；本范围文档不能据此宣称它们已具备生产能力。编辑器生产化的实现继续由该模块负责，只有第 5 节的业务交接纳入本迁移。

## 4. 目标业务流程

### 4.1 新课程

现有创作入口创建课程 → 保存作者归属和私有草稿 → 编辑器交付不可变修订及可预览产物 → 提交首次审核 → 管理员通过或退回 → 退回后修订重提 → 校验当前批准修订 → 发布首个正式版本 → 进入公开目录。

不在这条流程前重新增加 GitHub 地址/ZIP/Agent 上传等入口。管理员批准的是明确修订；作者随后编辑不会混入已经批准的首版。

### 4.2 已发布课程共创

选择正式版本 → 创建本人私有工作区并固定基础版本 → 使用现有编辑器修改 → 保存修订及预览 → 提交共创建议 → 管理者查看差异和评分 → 通过或要求修改 → 校验并合并 → 生成待发布版本 → 管理者确认版本号和说明后发布。

GitHub 管理的课程继续关联真实仓库 ID、分支、PR 和 SHA，核验远程状态，不以“请求已发送”认定已合并。工作区隔离是必需行为，但不要求每位用户拥有个人 GitHub Fork；无需个人 GitHub 的托管方式应保留。个人 Fork 作为可选能力适配，不能成为在线共创的前置条件。

### 4.3 学习与更新

学习者读取已发布且有权限的版本 → 记录课程、版本和学习方式 → 收藏或继续学习 → 发布新版时提示可切换 → 学习者主动切换或继续当前可用旧版。

预览、自动保存、审核通过、PR 合并和 `npm run build` 成功，都不能单独改变正式学习版本。

### 4.4 清理与恢复

审核仍在进行时保留工作分支；成功合并后，仅清理归属明确的临时审核分支，保留 PR 和贡献历史，并补偿清理此前已合并的遗留分支。不能删除外部贡献者分支或共享仓库。

个人删除、下架和永久删除分别处理。删除前保存意图并协调在途任务；外部结果确认后再清理关联；失败可重试。历史正式版本、贡献和共享文件是否可删除由引用及业务规则决定，不能按文件夹直接整目录删除。

## 5. 与现有编辑、预览的必要交接

无需重写编辑器，但编辑器与业务后端必须有明确契约。以下是所需信息，不规定最终 HTTP 路径和字段拼写。

| 交接信息 | 作用及约束 |
| --- | --- |
| 课程 ID、模块 ID | 课程发布单元使用稳定 ID；保留现有 `moduleIdentity.id`，建立课程与模块关系，不因改名重建身份 |
| 当前用户 | 后端从可信会话取得身份；客户端不能指定作者 ID 或管理员角色来获得权限 |
| 工作区 ID、基础版本 ID | 标识谁基于哪一正式版本修改；审核和合并检测基础版本冲突 |
| 修订 ID、内容摘要/SHA | 保存后生成不可变修订；审核、评分、预览和发布都绑定该修订 |
| 文件与产物引用 | 源码、素材、可播放内容关联同一修订；由编辑/构建模块交付，迁移不新增上传产品入口 |
| 预览引用与授权 | 复用现有预览，对作者及获授权审核者开放；文件请求同样检查权限，不只隐藏页面按钮 |
| 提交审核、读取意见 | 编辑器显示审核进度和退回意见；提交后继续编辑产生新修订，不覆盖审核对象 |
| 发布状态与正式版本 | 展示待审核、需修改、待合并、待发布、已发布或失败；正式版本由后端成功确认，不能由浏览器自行标记 |

当前部分课程注册使用构建期 `import.meta.glob`。要让其他学习者看到新发布内容，需要课程版本与可播放产物的加载接入；这是发布链路的必要工作，不能以“不迁移预览”为由省略。具体采用独立课程构建还是版本化数据加载，应保持现有课程交互完整，不用缩略图快照冒充正式互动页面。

## 6. 用户和权限边界

统一身份提供“这个人是谁”，本产品决定“这个人可以管理哪些课程”。第一阶段先用 Demo 共用密码和测试账号跑通登录及权限；身份验证封装为可替换适配器。后续接入减论 API，通过全局唯一 UUID 关联业务用户；不能把接口方案当作已完成实现。

- 验证身份后关联稳定业务用户 UUID；如接入减论，可信减论 UUID 与业务用户建立唯一映射，协议、字段和回调方式联调时确认。
- 普通学习者、课程作者/所有者、课程管理者、平台管理员的访问范围明确区分；不照搬 Demo 全局角色就允许管理所有课程。
- 减论新用户初次登录默认普通用户；Demo 测试角色由显式初始化配置。外部昵称、邮箱、GitHub 用户名及未经验证的角色字符串不能授予管理权。
- GitHub 数字身份与业务用户关联，服务端保管授权；未绑定 GitHub 不妨碍使用托管私有共创。
- 所有权转移、管理员授予/撤销、下架、删除、审核和发布都留审计记录；课程作者不能通过改请求参数自审自并。
- 用户和后台服务调用方分别鉴权；内部系统 Token 不进入浏览器，账号停用及权限撤销需要影响后续访问。

## 7. 数据保存范围

| 数据类别 | PostgreSQL 保存什么 | 文件或其他系统保存什么 |
| --- | --- | --- |
| 用户与授权关系 | 业务用户 UUID、可信外部身份映射、必要资料、课程所有权、管理授权、GitHub 身份关联 | 身份系统保管密码；服务端凭证配置保管密钥、外部访问令牌等秘密，不作为普通业务字段返回 |
| 课程与模块 | 稳定 ID、名称/分类/简介、所有者、模块关系、可见性、上下架、当前正式版本引用 | 原课程源码及素材保持文件形式 |
| 私有工作区与修订 | 所有者、来源课程/版本、修订摘要、状态、文件清单引用、冲突检查信息 | 草稿源码、图片、视频、预览和生成材料保存在按归属隔离的本地桶 |
| 审核与评分 | 审核对象及修订、意见、决定、审核者、评分及失效记录、提交/退回/重提时间 | 差异所需文件可由对应固定修订读取，不把整套课程作为审核 JSON 正文入库 |
| 合并与发布 | 基础和目标修订、PR/SHA/合并结果、版本号、说明、产物摘要、发布者、时间、回滚关系 | 每版可播放文件及其依赖素材按不可变引用保存 |
| 目录与贡献 | 可检索目录、索引刷新状态、贡献事实、身份快照、入版关系、质量分及可重建排名投影 | 不以静态开发者名单替代贡献事实 |
| 反馈与消息 | 课程/版本、反馈者、问题、Issue 映射、处理进度、接收人及各自已读时间 | 附件保存在桶内，数据库仅关联受控引用 |
| 个人记录 | 用户收藏、学习课程/版本/方式、最近学习时间；账号隔离与上限规则 | 课程内实验细节和既有遥测仍按原模块职责维护，不重复建设一份相同状态 |
| 任务与审计 | 队列、幂等键/请求摘要/回执、租约、心跳、检查点、重试、错误摘要、操作者和关键事实 | 大型诊断文件及恢复材料保存在受控运行目录；审计不记录秘密和完整令牌 |
| 文件索引 | 对象键、SHA-256、大小、MIME、路径及课程/修订/版本引用关系 | 课程字节留本地桶，不存 `bytea`，不换成 Base64 或整包 JSONB 入库 |

PostgreSQL 使用按实体划分的关系表、外键、唯一约束、索引及短事务。限量结构化检查点或扩展字段可用 JSONB，但不能取代整个业务模型。普通操作按需读写相关记录，不读取全库快照或整门课程文件。

本地桶先写文件并校验，再提交数据库引用；失败可能留下未引用文件，垃圾回收需避免并发及备份竞态。数据库和桶要成套备份并验证恢复，仅恢复数据库不足以恢复课程。主业务数据库不可用时明确失败，不回退到旧 JSON、浏览器缓存或播种空库。

新项目采用自身的数据库结构迁移，不机械复制 Demo 的 37 类模拟表、历史 `source_*` 兼容元数据及所有导入脚本。复用其事务、约束和恢复经验；只为确认需要保留的历史数据编写一次性迁移工具。`local-tables.json` 和 `db.json` 不成为最终产品运行依赖。

## 8. 任务与外部系统的迁移边界

- 必需任务：共创修订处理、差异生成、合并确认、发布、贡献刷新、反馈处理、目录刷新、分支清理和删除恢复；任务具体拆分按最终实现确定。
- GitHub 课程继续接收验签 Webhook，按投递 ID 去重，周期校准漏收/延迟事件；查询接口只读本地业务记录，不每次访问实时扫描 GitHub。
- 外部操作没有与 PostgreSQL 共享的事务。先持久化操作意图和检查点，调用后记录可核验结果；返回不明确时查询远程事实，不盲目重复合并、发版或删除。
- 相同请求重试返回已有结果；相同幂等键配不同内容应拒绝；课程相关任务互斥，陈旧租约不能提交新状态。
- 启动先确认数据库结构、桶和依赖就绪再接收请求；关闭时停止接单并等待在途操作，重启后可继续恢复。不能把已有训练任务队列自动等同于课程发布队列已实现。

## 9. 实施顺序和完成标准

以下为工作顺序，不表示现在开始编码。

| 阶段 | 交付范围 | 验收重点 |
| --- | --- | --- |
| A：身份与数据基础 | M02、M13；课程/模块/修订身份、权限及本地桶关系；现有课程登记 | 先按测试账号验证隔离、会话与权限；数据库约束生效；没有 Demo API 依赖；已有模块能继续播放 |
| B：审核与发布 | M01、M04、M06 和必要编辑器交接；M12 的发布任务基础 | 草稿不公开，退回可重提；批准绑定修订；发布失败保留旧版；他人能加载新正式版 |
| C：私有共创与贡献 | M03、M05、M08；合并核验、评分、入版及临时分支清理 | 私有隔离、自审禁止、新提交撤销旧审批、并发冲突处理；来源可追溯，历史不丢 |
| D：平台治理与服务 | M07、M09、M10、M11 | 下架/删除恢复、反馈消息隔离、收藏/续学、版本选择、外部接口权限与分页 |
| E：恢复与上线验收 | 完整 M12；所有范围的集成、容量、备份/恢复和故障验证 | 重启、重复请求、外部超时、数据库故障及文件缺失处理可靠；发布、回滚和数据恢复可验证 |

现有内置课程进入新业务目录时，建立模块到课程的映射和初始基线。是否作为管理员明确批准的既有版本导入需记录，不因源码可访问就伪造历史审核、贡献评分或发布事实。不为接入既有课程而新增面向用户的多来源导入功能。

最小端到端验收必须覆盖：

1. 作者 A 创建并编辑课程，学习者 B 不能读取私有草稿；管理员 C 退回，A 修改重提后批准首版。
2. 产物校验成功才发布；B 可打开正式互动页面，页面依赖的图片、训练和问答服务仍可用。
3. 共创者 D 从指定正式版本建立私有工作区；A/D 不能越权读改他人草稿；管理者查看差异、评分和合并后单独发版。
4. 审核后提交发生变化，旧批准及评分失效；发布失败、远程结果不明或重复请求不会把错误版本设为正式版本。
5. 新版发布后旧版可按规则继续学习；收藏和具体版本记录跨浏览器保留；反馈关联正确版本，消息仅接收人可读。
6. 删除本人工作区不会删除共享仓库或抹掉官方贡献；成功合并后可清理临时审核分支；下架立即阻止后续受限读取。
7. 服务重启能恢复未完成任务；数据库与本地桶成套恢复后课程可播放；最终产品独立启动，不需要 shukuDemo_server 运行。

## 10. 实施前需要落定的适配事项

这些是实现选择，不改变 M01～M13 的确定范围：

- 第一阶段明确测试账号、服务端共用密码配置及会话规则；减论用户身份接口和账号停用方式在后续正式接入前确认，不阻塞 Demo 登录验证。
- “课程”发布单元与现有多个模块的关系；`moduleIdentity.id` 如何关联课程 ID、工作区及正式版本。
- 当前编辑器提交修订、产物和预览的接口，以及生产环境尚未具备能力的交付责任；不把该模块未完成的功能默认为已完成。
- GitHub App 的实际组织、权限及课程仓库映射，哪些课程使用真实 PR；外部 PR 自动补录复用相同审核链路，不扩展成 GitHub 课程导入入口。
- 课程产物的版本化加载方式、素材冻结与缓存策略、本地桶路径，以及已有 Cloud 身份/缓存/遥测服务的边界。
- 是否保留任何 Demo 内容及其归属清单；仅按第一阶段需要显式初始化测试账号，不迁移原库业务测试数据，不进行账号认领或整库复制。
