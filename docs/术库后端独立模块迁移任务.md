# 术库后端独立模块迁移任务

任务状态：实施中。前端登录、私有修订预览与本地课程审核发布已打通，完整迁移尚未完成；详见 [迁移进度与验证](术库后端迁移进度.md)。原 `idl_backend` 未修改，未部署或切换现有服务。

## 1. 目标与边界

在 `backend/src/shuku_backend/` 新增 Python 包，承接 [术库业务逻辑迁移范围](术库业务逻辑迁移范围.md) 的 M01～M13。现有 `backend/src/idl_backend/` 保持不变，新模块通过适配层调用已有能力。

最终产品为 intuitive-deep-learning，运行时不依赖 shukuDemo_server。Demo 只作为业务规则和测试场景参考，不照搬 Node.js 后端、页面或旧数据库兼容层；第一阶段允许复用 Demo 共用密码和测试账号登录规则。

- 保留当前课程、SceneDeck、创作编辑、预览、训练、问答和缓存实现。
- 不迁移 GitHub 地址导入、ZIP 导入、本地 Agent 上传等多来源接入流程。
- 术库主业务使用 PostgreSQL；源码、素材和课程产物保存到本地文件桶。原有 SQLite、Cloud MySQL 缓存及遥测职责保持独立。
- 第一阶段先用 Demo 共用密码和测试账号跑通流程；后续再接入减论 API。减论 UUID 全局唯一，正式接入时首次创建账号、后续沿用；没有存量用户认领任务，不导入 Demo 的课程及其他测试业务数据。

## 2. 模块怎样组织

依赖方向：**页面／编辑器 → shuku_backend → 自身业务存储与外部系统；需要计算时 → 适配层 → idl_backend 或其现有服务。**

`idl_backend` 不导入 `shuku_backend`，不在原包中添加术库表、审核逻辑或发布队列。现有能力不适合直接调用时，在新包中做协议转换，不修改原实现来迎合术库。

建议先采用以下结构，按实际复杂度拆分，避免过早细分：

```text
backend/src/shuku_backend/
  __init__.py
  __main__.py          # 独立启动入口
  application.py       # 配置、服务组装、启动与关闭
  api.py               # 术库接口、身份上下文、请求及响应
  services.py          # 课程、审核、共创、发布等业务规则
  storage.py           # PostgreSQL 访问、事务、文件引用
  files.py             # 本地桶、哈希、引用及受控读取
  workers.py           # 持久任务、租约、重试与检查点
  adapters/
    idl.py             # 调用现有计算／问答能力
    identity.py        # Demo 验证先行，后续接入减论 API
    github.py          # GitHub API、Webhook、结果核验
  migrations/          # 术库业务表的结构迁移
backend/tests/shuku_backend/
```

以上目录按阶段创建；当前已有基础模块，GitHub 等后续适配尚未创建。安装时确认 `backend/pyproject.toml` 的包发现和迁移资源包含新包；需要增加依赖时使用独立可选依赖组，不让现有计算环境被迫安装术库数据库依赖。

### 可以复用什么

| 现有入口 | 复用方式与边界 |
| --- | --- |
| [contracts/client.py](../backend/src/idl_backend/contracts/client.py) | 可复用 `request_json` 等基础 HTTP 能力；超时、身份及错误转换由新适配层处理，不把调用方参数直接当权限 |
| [contracts/tasks.py](../backend/src/idl_backend/contracts/tasks.py)、`vision/`、`assessment/` | 使用已有任务契约或服务接口请求训练和问答；不复制计算实现，不为术库审核改动计算调度 |
| [local/cloud.py](../backend/src/idl_backend/local/cloud.py) | 参考已有 Cloud 定位和配置方式；Cloud API 位于另一仓库，实际可复用能力需联调，不能假定本仓库已包含完整云端服务 |
| [local/content_http.py](../backend/src/idl_backend/local/content_http.py) | 保留学习事件采集；按账号持久化的收藏、续学及消息由新业务模块负责，不把本地遥测 Cookie 当用户登录 |
| [jobs/local.py](../backend/src/idl_backend/jobs/local.py) | 继续承接计算任务；其本地内存任务不能替代审核、合并、发布的持久化任务 |
| [现有创作模块](../src/creator/README.md) | 通过交接契约接收修订、产物及预览引用，复用编辑与展示；浏览器草稿不等于后端已保存版本 |

直接调用 Python 函数仅用于适合进程内运行的已有能力；计算和 Cloud 服务优先走已有接口。单独封装适配层，避免业务模块到处引用原包内部实现。

| T02 身份、权限与存储 | M02、M13 | 用 Demo 共用密码和测试账号完成登录、退出、会话过期及权限校验；预留减论身份适配；课程归属、管理授权、事务与唯一约束生效；建立课程／模块／修订及文件引用模型 |
| T03 编辑器交接 | M02、M04、M06 | 保存不可变修订，关联源码、产物、预览和内容摘要；作者和审核者受控访问；正式版加载真实互动内容，而不是预览截图 |

T01 起即提供基本持久任务能力；T07 是补齐各业务链路，不允许前期用进程内任务冒充可靠发布。

### 登录分两阶段实施

**第一阶段：Demo 登录跑通业务。** 在 `shuku_backend` 中实现测试账号查询、共用密码验证、登录会话、退出、过期和失败次数限制。共用密码通过服务端 `SHUKU_DEMO_PASSWORD` 配置，不写进代码或接口响应。通过显式初始化准备固定 UUID 的学习者、作者／课程管理者和平台管理员测试账号；不读取 Demo 的整库数据，不在正常启动时反复播种账号。

验证器负责返回已验证的业务身份，权限仍由术库业务记录判断；客户端不能通过指定账号 UUID 或角色绕过密码验证。页面使用这些账号完成创建、审核、共创、发布、收藏和反馈等端到端流程，不要求先有减论接口。

**第二阶段：替换为减论 API。** 保持相同的身份结果和会话接口，由减论验证器返回可信 UUID，再关联术库业务账号。后续只切换身份提供方，课程、审核和权限业务不依赖 Demo 密码验证实现。可规划 `SHUKU_AUTH_PROVIDER=demo|jianlun` 配置；选择减论模式时明确关闭 Demo 登录，不在接口故障时自动降级。切换前可清理测试账号及测试业务数据，不增加测试账号认领迁移。

Demo 验证器已实现并通过隔离库测试；减论验证器尚未实现。第一阶段验收不以减论联调为前置条件；正式使用减论账号前再完成真实接口联调和相应测试。

### 编辑器交接必须先确定

至少包含课程 ID、`moduleIdentity.id`、工作区 ID、基础正式版本、不可变修订 ID、文件清单与摘要、产物及预览引用。用户身份由后端可信会话确定，客户端不得自行指定作者或管理员身份。

编辑器提交修订与产物的内部交接属于本迁移，不新增面向用户的 ZIP 上传入口。只有审核、产物核验和发布均成功，才能更新正式学习版本。现有构建期课程注册如何加载新发布版本，需要作为 T03 的实际交付，不能只完成数据库记录。

## 4. 数据、任务与运行接入

- **数据库**：新建术库业务表及迁移记录，初期与现有数据隔离；不机械复制 Demo 的 `source_*` 和旧 JSON。普通操作按需查询，不读写全库快照。
- **文件**：先保存并校验文件，再提交引用；访问时检查课程／修订权限。删除需检查共享引用，失败可重试，不能整目录清除其他用户内容。
- **外部操作**：先保存意图和检查点，再调用 GitHub，核实结果后更新业务状态。网络超时不等于操作失败，重试前先查远程事实。
- **任务**：持久化队列与租约，陈旧执行者不能覆盖新结果；重复请求复用回执。计算队列与术库发布队列保持各自职责。
- **启动**：建议通过 `python -m shuku_backend` 独立运行，现有 idl 服务继续运行；统一网关接入术库接口，例如待确定的 `/api/shuku/`，避免覆盖现有 `/api/lab`、`/api/ai` 和遥测路由。
- **外围配置**：后续只按接入需要调整依赖、代理、部署和前端调用；单独评审这些改动，不为接入直接改写 idl_backend。关闭新业务入口即可停止新模块接单，已提交数据和待处理任务仍需保留及恢复。

主业务数据库不可用时明确失败，不回退到 JSON、浏览器存储或自动播种空数据。减论和 GitHub 凭据只在服务端配置，不复制 Demo 的环境文件。

## 5. 测试与完成条件

每个任务补充对应测试，迁移完成至少证明：

1. 原 `idl_backend` 代码无改动；现有计算、训练、问答及课程播放的相关测试和验证通过。
2. 新模块独立启动，原包没有对新包的反向依赖；最终运行不调用 Demo 服务。
3. 第一阶段验证测试账号密码正确／错误、失败限次、退出和会话过期，以及不同角色的资源隔离；他人不能读写私有修订，无权限者不能审核或发布。第二阶段再验证同一减论 UUID 并发登录只关联一个术库账号、减论接口故障不退回 Demo 登录。
4. 审核绑定修订、禁止自审、批准失效、合并核验、发版失败保留旧版和历史版本续学均通过。
5. 上下架、删除、共享文件保护、贡献排名、反馈和消息已读按账号正确处理。
6. 重复请求、进程重启、过期租约、GitHub 超时、数据库故障及文件缺失有明确结果，不产生错误公开内容。
7. 数据库与文件联合恢复后，已发布课程可完整播放，图片及计算接口仍可用。

文档完成不代表功能迁移完成。实施时每项任务都需要有真实运行证据，不能仅把任务状态改为“完成”。

| 决策 | 原因与代价 |
