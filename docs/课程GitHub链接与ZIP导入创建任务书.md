> 状态：已按用户后续指令进入实施与验收。更新时间：2026-10-29。
> 原“仅修改 Markdown”的限制已由用户后续“开始功能实现”指令解除。本次复用现有任务表，不新增数据库迁移；验收使用独立测试库与 GitHub 夹具，不以真实用户创建测试课程或仓库。

## 一、任务目标与完成定义

用户通过 GitHub 课程目录链接或课程 ZIP，初始化一门属于自己的课程。两种入口共用标准课程包处理流程，保留可编辑源码，复用现有审核、构建、私有仓库和版本发布能力。

整体交付必须同时满足：

1. 两种入口均能识别课程内容并展示确认信息。
2. 用户确认后只创建一个归本人所有的私有草稿，原课程不受影响。
3. 草稿能够以自学互动、教学展示两种模式预览，且可以继续编辑、保存。
4. 在 `reduct-shuku` 初始化属于该课程的私有仓库，真实源码和素材已提交并核对成功。
5. 后续网页或本地 Agent 编辑、审核、正式发布均可接续；导入本身不等于审核通过或发布。
6. 错误、重复请求、重启、取消和删除均有明确结果与恢复方式。

“识别成功”“创建空草稿”“只建了带 README 的私有仓库”均不算需求完成。各阶段可分批交付，但不得将部分完成标为整体完成。

## 二、本期范围

| 项目 | 本期要求 |
|---|---|
| GitHub 来源 | 公开仓库中的标准 React 课程模块，支持指定子目录，解析并固定到 commit SHA |
| ZIP 来源 | 标准 React 课程模块，支持一个外层目录或标准 `modules/<课程>` 布局 |
| 统一包 | 大纲、源码、素材、页面入口、来源、许可证、固定运行依赖和内容摘要 |
| 固定依赖 | 优先适配现有 `course-template` 运行契约，校验共享组件兼容性，不能盲用最新版 |
| 可编辑性 | 源码导入，不把源课程截图化、纯静态化来替代可编辑工程 |
| 课程归属 | 复用当前 creator/admin 创建权限，owner 为当前术库账号 |
| GitHub 目标 | `reduct-shuku/course-<course_id>`，初始化为 private |
| 框架内容 | 课程仓库只保存课程及必要元数据，不上传全量平台框架 |
| 本地文件 | ZIP、源码、媒体、构建产物保存在本地文件桶；数据库保存业务关系与对象元数据 |
| 原课程更新 | 导入时固定来源，后续更新必须显式发起，不自动覆盖用户修改 |
| 审核与发布 | 沿用既有流程，未审核、未发布的导入课程不进入公共首页 |

本期不包含：任意 Vue/Next.js/服务端项目运行、自定义 npm 构建脚本执行、普通 HTML/dist 专用导入器、私有源仓库授权接入、数据库引擎迁移、自动跟随原仓库更新。

“初始化私有”已经确定；“正式发布后是否仍永久私有”不在本任务中默认为已确定。现有发布代码可能调整仓库可见性，实施时需在产品规则和界面上明确，不能因导入而自动公开仓库。

## 三、固定验收样本

### 样本 G：GitHub 课程目录

```text
https://github.com/ReductTech/intuitive-deep-learning/tree/develop/modules/Visual-Generation-Guide
```

验收运行时先解析到具体源 commit，并记录该次使用的 SHA。源分支后来变化，不得影响同一导入任务的重试和构建。

### 样本 Z：用户本地 ZIP

```text
D:\WORK_DIR\00shuku\视觉生成html\intuitive-deep-learning-develop\modules\Visual-Generation-Guide.zip
```

由浏览器选择并上传，服务器不直接读取用户电脑的盘符路径。

已核查样本包含 119 个文件，压缩约 10.97 MiB，展开约 12.16 MiB。缺少包外共享组件；图片资源包含带泛型及 `query:'?url'` 的 `import.meta.glob`。按当前媒体 Base64 方式估算约 15.39 MiB，超过现有源码 12 MiB 限制。

因此必须解决共享依赖和二进制素材问题，不能只放宽 ZIP 上传大小。两个样本分别验收，不假定本地 ZIP 与在线目录是同一版本。

## 四、统一处理链路与状态

```text
选择来源
→ 上传/读取并固定内容
→ 识别课程、依赖、缺失项
→ 用户确认
→ 创建本人私有草稿与持久任务
→ 标准化源码和素材
→ 保存初始修订
→ 构建双模式预览 + 初始化私有仓库
→ 核对本地修订、远端文件与 commit
→ 进入“我的课程”继续创作
→ 用户另行提交审核与发布
```

识别阶段不创建仓库。存在多个课程时必须让用户选择，不能默认导入第一个。

识别、确认、源码准备、构建、GitHub 建仓、初始提交、最终核对的状态分别记录。构建失败与 GitHub 失败必须能够区分；“处理中”不能无限持续。父任务不能占着唯一 worker 或课程锁，阻塞自己创建的子任务。

课程业务状态仍使用现有草稿、发布、下架等含义，导入阶段另行记录。持久数据可复用现有任务台账或新增专用导入记录，须在 T01 明确唯一方案；本任务书不将某个尚未设计完成的新表写成已实现能力。

## 五、实施任务

### T01：标准课程包与运行契约

- 状态：[x] 已实现，自动化回归通过；前置：无。
- 确定统一包版本、源码路径、页面与自学入口、二进制素材清单、来源、许可和框架锁定字段。
- 课程必须获得新的平台身份；原 module UUID 作为来源信息及课程内素材映射保留，避免覆盖原课或破坏素材引用。
- 明确导入记录的持久存储、幂等键、过期策略及与既有任务/修订的关联。
- 约定网页编辑、本地 Agent、预览构建、GitHub 导出共用同一包契约，并保留旧格式兼容。
- 产出：包结构说明、字段约束、可读示例、兼容规则和持久状态设计。
- 主要位置：[source.py](../backend/src/shuku_backend/source.py)、[local-authoring.lock.json](../local-authoring.lock.json)、[local_agent_client.py](../backend/src/shuku_backend/local_agent_client.py)。
- 验收：同一包能被各环节理解，缺依赖可报告；格式版本和来源身份不会混为平台身份。

### T02：GitHub 与 ZIP 两种来源接入

- 状态：[x] 已实现，自动化回归通过；前置：T01。
- GitHub 链接解析 owner/repo/ref/子目录，支持含斜杠的 ref；固定 SHA 后读取课程和明确依赖，不默认拉取整个平台。
- ZIP 流式接收、校验后展开；支持约定布局，拒绝目录穿越、符号链接、重复路径、秘密文件和超限内容。
- 两种来源输出相同的待导入课程包及识别报告；ZIP 缺少可信 commit 时只记录摘要和用户声明来源。
- 多课程输入支持明确选择；本期不承诺自动合并多个课程。
- 产出：统一来源适配器、识别报告、大小/文件数限制配置及错误码。
- 主要位置：拟新增 `course_package.py`、`github_course_source.py`；接入 [api.py](../backend/src/shuku_backend/api.py)。
- 验收：样本 G、Z 均可识别；非 GitHub 地址、越权路径和不完整文件列表均不能伪装成成功。

### T03：标准模块转换与固定依赖适配

- 状态：[x] 已实现，自动化回归通过；前置：T01、T02。
- 提取现有标准模块转换的纯逻辑，复用页面包装、自学入口和课程元数据处理；不在后端调用客户端下载、CLI 或凭证逻辑。
- 校验实际页面与大纲，不能将尚未实现的页面计为可学习内容。
- 适配样本中的图片 glob、共享组件及素材位置；限定支持的语法，不以泛化字符串替换改写整个课程。
- 选择并固定兼容的运行 profile；缺共享组件或 API 不兼容时输出明确报告。
- 产出：可编辑标准工程、双入口、兼容性与转换记录。
- 主要位置：[local_agent_client.py](../backend/src/shuku_backend/local_agent_client.py)、[shuku-source-plugin.mjs](../scripts/shuku-source-plugin.mjs)、[build-shuku-preview.mjs](../scripts/build-shuku-preview.mjs)；拟新增纯转换模块。
- 验收：两个实际样本可进入后续构建；不依赖把用户代码写进平台 `modules/` 再重新部署。

### T04：源码、二进制素材与编辑保存闭环

- 状态：[x] 已实现，自动化回归通过；前置：T01；可与 T02、T03 部分并行。
- 文本源码与二进制素材分开保存，媒体走本地文件桶，修订记录不可变对象清单。

### T05：确认创建、课程归属与异步构建

- 状态：[x] 已实现，自动化回归通过；前置：T02、T03、T04。
- 用户确认才创建本人私有草稿、初始修订及持久任务。相同确认请求重复提交只得到一个课程。

- 产出：确认与任务服务、状态查询、重试逻辑和可预览修订。

## 六、统一包契约示例

以下保留方案阶段的字段语义。实际落地协议使用 `sourceFormatVersion:2`、`source.files`、`sourceAssets` 和 `importOrigin`；完整字段、限额、API 与验证命令见[实施说明](shuku-course-import.md)：

```json
{
  "formatVersion": 2,
  "sourceType": "github-or-zip",
  "sourceIdentity": {
    "repository": "ReductTech/intuitive-deep-learning",
    "commit": "<已核对的源提交或空值>",
    "path": "modules/Visual-Generation-Guide",
    "archiveSha256": "<ZIP摘要或空值>"
  },
  "runtime": {
    "repository": "reduct-shuku/course-template",
    "commit": "<固定且兼容的框架提交>"
  },
  "textFiles": {},
  "binaryAssets": {},
  "entries": {
    "guide": "<自学入口>",
    "deck": "<教学入口>"
  }
}
```

源码内容与二进制主体保存在文件桶，字段中的对象引用必须带大小、MIME、摘要和授权关系。入库的业务元数据、导出到 GitHub 的课程文件和发给编辑器的协议均需有明确映射，不能各自发明一套无法往返的结构。

## 八、测试与交付规则

- 测试覆盖链接解析、固定版本、ZIP 安全、依赖适配、二进制保存、归属隔离、幂等、远端对账、超时回收和删除补偿。
- 用小型完整夹具覆盖规则，用两个真实样本完成集成验收；不把 11 MB ZIP 直接提交为普通单元测试夹具。

- 不因本功能切换数据库引擎，不把文件改存 bytea/blob，不将平台框架批量复制到课程仓库。
- 不通过改平台公开课程目录或公开仓库扫描器实现用户私有导入。
- Demo 与产品的域名、配置、凭证和部署边界分别维护。
- 修改前同步远程，修改后运行全部相关验证，再按仓库规则提交推送；文档更新不代表功能已经上线。
