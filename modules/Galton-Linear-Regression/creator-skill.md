# 课程创作 Skill

## 使命

把老师的一段想法、教材、截图、数据或问题，发展成一套真正能帮助人理解的 React 课程。交付物可以同时成为课堂投影用的 1600×900 Web PPT 和课后探索用的 Blog/Guide，但两者共享同一条认知旅程，而不是两套互相复制的页面。

课程的成功标准不是“组件齐全”或“交互很多”，而是学习者能更快看见关键关系、形成预测、发现反例，并用自己的话解释结论。

## 创作总原则

### 先创造课程，再选择组件

不要从卡片、按钮或既有页面结构开始。先找出这门课最值得被看见的关系、变化、冲突、尺度或转折：

- 一次观察会改变什么判断？
- 哪个反例最能打破直觉？
- 学习者应该先看到证据，还是先提出猜测？
- 哪个历史人物、真实场景或具体数据能让抽象概念有重量？

每门课都要形成自己的视觉隐喻和界面性格。数学可以像实验台、地图、推演纸；历史可以像档案、时间轴、展览；编程可以像调试现场、机器内部或逐步展开的日志。可以大胆选择形式，但形式必须由知识本身解释得通。

### 让基座模型主动发挥能力

模型不只是把文字翻译成 JSX，也不只是执行固定模板。它应主动完成这些创作工作：

- 从材料中提炼事实、隐含主张、学习障碍、情绪线索和未决问题；
- 根据目标学习者补齐合理的背景、例子、反例、类比、练习和延伸阅读；
- 提出多个教学隐喻或页面构图，比较它们的认知收益后选择一个；
- 把抽象关系变成图表、时间线、数轴、模拟、对照实验、标注图或可操作的模型；
- 预测学习者最可能的误解，并在页面中安排最短的纠偏路径；
- 在没有合适素材时，主动生成 SVG、CSS 图解、数据可视化或必要的插图；
- 根据内容判断一页应该是观察、叙事、解释、推导、练习、实验、总结还是过渡，而不是把每页都做成同一种“互动卡片”；
- 在需求不完整时做出合理假设并继续推进，只把会改变课程方向的关键不确定性留给老师确认。

约束是边界，不是创意的替代品。不要因为担心偏离模板，就把课程做成安全但平庸的通用页面。

## 从输入到课程结构

1. **建立教学 brief**：明确目标学习者、已有知识、授课时长、必须保留的事实，以及学习者最后应该能做什么。
2. **找到中心问题**：把主题改写成一个需要证据、推理或操作才能回答的问题。
3. **设计认知旅程**：安排“看见 → 猜测 → 比较 → 解释 → 应用 → 回顾”的节奏。默认规模约 22–28 页，但页数服从内容密度和课堂节奏。
4. **为每页选择表达方式**：写清这一页的主问题、学习者首先注意到什么、页面如何通向下一页，以及为什么此处需要或不需要交互。
5. **再实现**：先用 Shared UI Kit 组合语义、排版、反馈和流程，再把真正属于本课程的图表、公式、动画和媒体放入模块目录。
6. **回看整套课**：检查是否有重复页面、无意义交互、信息跳跃或缺少反例；删掉不能提升理解的东西。

## UI Kit：统一语法，保留个性

大幅复用 `modules/shared/react/`，把 UI Kit 当作课程的语义语法，而不是视觉牢笼。

- 按钮、链接按钮使用 `Button`；数值控制使用 `RangeControl`；互斥选择使用 `Select`；说明触发器使用 `ExplainPanelButton`。
- 标题、正文、标签、公式说明使用 `Typography`；内容阶段使用 `LessonStage` / `ContentBlock`；反馈使用 `Callout` / `NoticeStrip`；指标使用 `ValueTile`。
- 普通 UI 不要重复造轮子。原生按钮、输入框只用于 UI Kit 无法表达的领域专用操作，例如画布工具、图例、棋盘格、拖拽标注；此时仍复用 Typography、token、焦点状态和可访问性行为。
- 模块 CSS 可以创造课程的空间、图表和视觉隐喻，但不要重写 UI Kit 的字体、字号、字重、行高或基础控件外观。
- 先组合现有组件；当一个模式跨课程稳定出现，再把它提升到 `modules/shared/`。不要从 `modules-legacy/` 引入运行时代码或资源。

## 页面节奏与交互判断

- 交互页默认不超过整套课程的 50%。交互只有在它能带来新证据、让学习者做预测、比较假设、暴露误解或完成推理时才值得加入。
- 非交互页可以是历史证据、观察图、连续解释、公式推导、案例、反例、总结或过渡。克制不是缺内容，而是把内容组织得更快被理解。
- 不要求每页使用同一种排版。布局随认知任务变化：档案页、图表页、推导页、实验页、总结页可以拥有不同构图，只要阅读顺序明确。
- 无交互页使用 UI Kit 流程控制“模式 2：下拉提示”提示下一页：优先使用 `LessonFlow` 的 `revealMode: 'cue'`、`ScrollCue` 或 `ProgressiveReveal mode="cue"`。不要添加只为推进流程的假按钮。
- 有交互页可以使用 `cue`、`scroll` 或 `immediate`，由页面的认知节奏决定。模式 2 是轻量的方向提示，不代替内容本身的证据和反馈。

## 内容、媒体与素材

内容要有层次：真实背景、概念骨架、具体例子、反例或常见误解、一次练习/预测、阶段总结和延伸阅读。每页保留一个主问题，但整套课要让学习者感到知识在展开，而不是同一结论被换皮重复。

在图片、历史档案、地图、照片或外部媒体确实能提升理解时，可以联网查找和下载。素材应：

- 保存到对应模块目录，不在运行时依赖远程地址；
- 记录来源、作者、许可或访问日期，优先使用公共领域和开放许可；
- 承担证据、叙事、定位或比较作用，而不是装饰性填空；
- 没有合适素材时，优先用 SVG/CSS/Canvas 或 AI 生成插图，并说明用途与来源。

## Web PPT 与实现边界

- PPT 画布为 1600×900，内容自然收进画布，不依赖裁切隐藏溢出。
- Grid/Flex 子项使用可收缩轨道和 `min-width: 0`；媒体、公式、SVG、Canvas 和交互控件使用 `max-width: 100%`。
- PPT 是课堂观看方式，不是把网页压扁成截图；Blog/Guide 是课后探索方式，不是另一套课程。
- 使用模块 Provider 共享状态，处理 hydrate、错误、加载、重置和回访体验。

## 交付前的创作复盘

交付前不要只问“有没有报错”，还要问：

- 这门课最有辨识度的教学隐喻是什么？它是否真的来自知识本身？
- 哪些页面主动利用了模型的推理、改写、举例和可视化能力？
- 交互是否少而有力？删掉一个控件后，理解会不会变差？
- 每一页是否有一个清晰主问题，下一页是否自然成为答案或新问题？
- UI Kit 是否承担了共性的可访问性和状态处理，而模块代码是否只负责独特的知识表达？
- 哪些事实来自材料，哪些是设计推断，哪些需要老师确认？

最好的模块不是最像模板的模块，而是只有这门课才能长成的模块。
