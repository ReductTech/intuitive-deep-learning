# SceneDeck 创作原型

`/scenedeck/`、`/web_ppt/` 和 `/edit-deck` 共用创作工作区；首页提供“创作课件”入口。`?deck=<课程 ID>&slide=<页面 ID>` 可定位课程和页面。缩略图采集模式继续走原播放器，旧本机编辑器保留在 `/edit-deck/legacy`。

## 可体验的流程

1. 左侧默认采用 PPT 式缩略图与页码；“显示大纲”按钮可展开标题，默认隐藏。每页旁边的“⋯”直接打开页面属性，编辑标题、教学目标、摘要、交互设计、页面衔接和讲稿；参考资料等额外字段完整保留。上下移动、复制与删除在属性面板的页面操作中，页码仍可拖动排序。
2. 空白页在下方填写要求并生成设计图；已有设计图直接填写要求并修改，不再打开生图弹窗。平台直接调用 Edit Deck 接口，自动携带当前设计图作为编辑参考。
3. 下方只有一个主要操作，按当前状态切换为生成/修改设计图、制作网页（模拟）、修改页面（模拟）或预览。大纲不再单独确认。
4. 继续修改、恢复上一版，或使用工作区的撤销与重做。
5. 自动保存到当前浏览器；通过导出/导入 JSON 备份可编辑作品，备份包含当前及历史设计图。

## 本阶段边界

- 本机开发模式支持双击网页中的静态文字原位编辑，Enter 或失焦保存到对应 TSX 源文件，Esc 取消。源码位置由开发服务解析并校验版本，修改后 Vite 热更新；不是 localStorage 文字覆盖。支持可定位的静态 JSX 文字与 ContentBlock 标题/副标题，跳过公式、SVG/Canvas 和运行时计算文字。静态部署没有本机源码写入能力。

- 生图是平台能力：复用 `Edit-Deck/api.ts` 与 Vite 本机 `/__edit-deck/config`、`/__edit-deck/image` 接口，沿用服务端已有配置。生成与图片编辑不通过智能体，密钥不进入前端。
- 生图依赖本机 `npm run dev` 服务，静态生产站点尚未部署对应代理。未配置时给出原编辑器的配置入口。
- 智能体网页修改仍使用本地预设模板；图片修改由输入框直接调用平台生图服务，与智能体执行分开。重新生成、恢复版本和讲稿放在页面次级菜单。
- 图片单独保存在 IndexedDB，项目和历史记录只引用图片 ID，避免原始图片撑满 localStorage。生成失败或取消会保留原页面，成功生成前不新增方案版本。
- 原课程始终使用原 React 页面渲染。生成设计图和模拟修改不会替换已有网页；设计图单独保留，可随时查看。默认打开、预览、全屏演示及离线快照优先使用已有网页。旧草稿因生图被标记“待制作”时，会自动恢复网页可用状态，不删除设计图或历史。
- 风格设置用于生图提示词与模拟页面。预览中的模拟完成状态不保存为学生学习记录；原课程内置交互沿用其原有行为。
- 每个课程保存一份当前浏览器草稿，不是云端作品库或多人协作。建议导出 JSON 备份。
- 页面属性从课程 `outlines.json` 的对应页面读取；旧草稿会补齐缺少的元数据。修改保存在作品草稿与版本中，不直接改动仓库原课程文件，也不会替换现有 React 网页。讲稿阅读和后续生图会读取修改后的属性。
- 离线导出为单文件 HTML：有真实设计图的页面使用原图快照，原课程使用已有的 400×225 缩略图快照，模拟页面导出基础 HTML 与示例完成按钮。支持离线翻页，不包含原课程的完整交互、视频或计算服务。图片缺失则报告失败，不生成缺页作品。
- 工作区撤销历史保留最近 20 次操作；页面方案版本随作品保存。

## 检查

```sh
npm run typecheck
node --experimental-strip-types --test src/creator/model.test.mjs
npm run build
```

后续云端接入应替换本地任务与存储适配，不把生成结果藏进对话文本；页面版本、大纲和确认状态继续作为项目数据维护。
